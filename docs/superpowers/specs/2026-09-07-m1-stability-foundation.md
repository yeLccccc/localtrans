# Spec M1: 稳定性与测试地基（stability-foundation）

> 里程碑：M1（RELEASE.md §三）。节奏位：功能实现第 1 站。
> 一句话：把"测试环境可信"和"发版键雏形"做实——后面每一站都踩在这块地基上。

## 目标
1. 夹具可一键恢复出厂（根治本周实证的漂移：旧共享路径/残留身份/脏信任表）；
2. 测试端口可配置（解锁并行泳道，关掉 ffi 存量 7-8 个端口类失败）；
3. run-all 一键入口 + 中继路径场景 + 零信任冷启动覆盖。

## 范围
**做**：L3 重置（PC+手机）、`LOCALTRANS_TEST_PORT_BASE` 偏移、`run-all.mjs`、中继 e2e 场景、冷启动配对场景、offer 弹窗 testid（测试基建欠账）。
**不做**：UI 改动、传输逻辑改动、手机传输页改造（M2）。

## 功能需求
- **FR1 L3 出厂重置**：`reset(3)` —— 停进程→备份并清空 data/（保留日志目录可选）→可选信任播种（给定 fp 列表写 trusted_peers.json）→重启进程→health 就绪。手机侧 `pm clear` 封装+权限自动放行（本周实证 MIUI 弹窗流程固化进 adb.mjs）。
- **FR2 端口可配置**：core 发现端口/QUIC 端口/中继端口支持 `LOCALTRANS_TEST_PORT_BASE` 偏移（不设=现状逐字节一致）。测试代码全部改用偏移，47600/47601 硬编码清零。
- **FR3 run-all**：`node tests/e2e/run-all.mjs` 串跑全部场景（顺序可控、单场景失败可继续、汇总 markdown 报告含每场景 PASS/FAIL 与证据目录链接）。
- **FR4 中继场景**：本机/WSL 起 relay → 双 PC 强制走中继（防火墙规则模拟隔离）→ 配对+传输全链断言（经中继路径的会话建立、字节核对、吞吐粗检）。
- **FR5 冷启动覆盖**：场景含"全新身份双向零信任→真实配对→传输"（P0-6 教训常态化）。
- **FR6** offer 弹窗补 testid（App.vue offer-modal 区）。

## 非功能
- 不设端口环境变量时行为与现状完全一致（回归锚单测）；
- relay 场景用独立端口段，不与常驻实例冲突。

## 验收标准
1. `run-all.mjs` 一键全绿（含 FR4/FR5 新场景），产出汇总报告；
2. `LOCALTRANS_TEST_PORT_BASE=50100` 下 `gate.sh core` 全绿且不占 47600/47601；不设时全绿；
3. ffi 存量端口类失败（stash 对照定责的那批）转绿或可解释；
4. L3 后双端身份/信任/共享区确如新装（场景断言）。

## 依赖与顺序
无前置。后续所有站依赖 FR3 的 run-all 与 FR1 的 L3。

## 风险
- 端口偏移触及 core 多处常量，需全量 grep 清零验证；
- 中继场景在单机模拟隔离的防火墙操作需可恢复（失败也要还原规则）。
