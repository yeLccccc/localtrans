# Spec P1: 打磨·传输卡视觉与速度平滑（polish-transfer-card）

> 节奏位：第三段（打磨）第 1 站。承载用户定案修订 R1/R2。
> 一句话：一个进度条、一条平滑的速度曲线。

## 目标
传输卡视觉简化 + 速度显示可信。

## 范围
**做**：FR1-FR4（PC+手机同步，两端一致）。**不做**：传输逻辑/事件频率改动（4Hz 泵保持）。

## 功能需求
- **FR1 R1 单进度条**：撤双进度显示与积压角标的视觉面；进度条唯一语义=**对端确认进度**（发送方取 remote_done、接收方取 done——两端语义统一为"真实完成度"）；remote_done 与积压检测保留为内部健康信号（触发"等待确认"文案态，不再渲染第二进度条/角标）。
- **FR2 R2 速度平滑**：速度显示=EMA（α 按显示间隔调）+ 滑动窗口（≥2s）+ 最小刷新间隔（≥500ms）；窗口内字节/时间计算，不用单事件瞬时值。
- **FR3 尖峰抑制**：块边界（4MB）完成瞬间不产生速度跳变（计入窗口而非当帧）；终态/暂停冻结当前值。
- **FR4 台阶感**：进度条 CSS 补间时长按 4Hz 调优（现 0.28s 基础上按视觉验证微调）；ETA 用平滑后速度计算。

## 验收标准
1. **速度曲线场景断言**：500MB 传输全程采样显示速度序列，无 >3× 中位数的单点尖刺，方差有界（写进场景，可自动判定）；
2. 传输卡视觉截图目检：单进度条三端一致（PC/手机/暂停态/等待确认态）；
3. 现有全部场景回归绿（视觉改动不破坏 testid 体系）。

## 依赖与顺序
依赖 V 段完成（有回归保护再动视觉）。打磨池中 R1/R2 两项关闭。

## 风险
- 平滑过度让启动加速感消失——窗口/α 取平衡，验收断言兼顾"无尖刺"与"趋势跟随"；
- 手机端性能（高频重渲）——最小刷新间隔天然限频。
