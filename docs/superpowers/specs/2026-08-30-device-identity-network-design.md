# 设备身份与网络管理设计(设备页 §A 发现层重设计)

> 日期:2026-08-30
> 版本基线:v0.11.0
> 状态:已与用户逐节确认(v3 定稿)
> 来源:设备页功能树梳理中用户提出"设备身份的自我定义需要好好设计——IP 的",经 brainstorming 澄清四项痛点全中(IP 展示单薄/找到我没设计好/身份与 IP 关系混乱/公网 IP 缺失),三版迭代定稿。

## 0. 背景与目标

现状三层混淆:指纹(身份)、地址(路由提示)、连接态(会话)搅在一起呈现,卡片裸露 SocketAddr 让用户把地址当身份;`primary_local_ip` 单选默认路由,VPN/多网卡时给出错误网段 IP;"别人怎么找到我"依赖人肉传单个 IP。

目标:身份/可发现性/地址三层概念分离;发现通道升级为"名片打包";新增通道质量管理与智能选路(用户无感);连接状态机理清 + 连接记忆制自动重连。

## 1. 设备标识(维持现状)

- **指纹** = SHA-256(cert.der),唯一标识;信任/权限/配对/中继租约全以它为键。key 持久化(data/identity.key),证书重签(固定序列号)字节级一致 → 指纹终身不变。
- **短码** XXXX-XXXX:设置页展示辅助,**不进任何流程**。
- **设备名**(自己改,即时广播)/ **别名**(我给对方起的):纯显示,无安全语义。显示优先级:别名 > 广播名 > 配对名。

## 2. 发现广播(维持机制 + 消息纪律)

- 包内容 6 字段永不扩:name/fingerprint/pubkey/quic_port/ts_ms/nonce。无 IP 字段(源 IP 由接收方从 UDP 包头读)、无目录、无能力清单——只够"认出我"。
- 节奏:常态 5s±1s(现状);新增静默期拉长(网络无对端活跃时 5s→15s,检测到对端活跃恢复 5s)。
- 中结名册:注册互见,hidden 即剔除(现状)。
- **隐身语义(定案,现状有一处修正)**:隐身只约束"被看见"——不广播、不回应探测、名册剔除;**出站探测放行**(我主动探测别人照发:点发现别人的任何主动行为不受隐身限制)。现状代码把出站探测也门控了(隐身时 ProbeNow/ProbeAddr/周期重探全跳过),逻辑不自洽——"能被动看广播却不能主动问",按本设计修正为放行。
- **去掉"刷新"按钮(定案)**:三个发现通道全自动化(同网 5s 周期广播+启动 3 连发 / 跨网重探表 8s 自动补探 / 中结名册推送制),不存在需要手动刷新的窗口;删除 PC 设备页刷新按钮与 Android 对应入口,空状态引导文案同步改为"等待网络中的设备出现(通常几秒内)"。
- **砍掉**:唤程码(v1 曾设计,名片 + 两通道已覆盖其场景,不再有此概念)。

## 3. 名片打包(新增,主发现通道)

### 3.1 名片内容

结构化文本,一键复制(45s 自清剪贴板,沿用 A7):

```
名字:小明的电脑  短码:AB3D-7F2C
局域网:192.168.1.5 / 10.0.0.3      ← 全部网卡地址,多行
公网:203.0.113.7:47601             ← 经中继问询所得,有则带;用户可勾选去掉(默认带)
中继:relay.example.com:9443        ← 配了中继则带
```

### 3.2 使用流程

- 对方在手动添加框粘贴名片全文(也接受裸 IP,兼容旧用法)→ 解析出全部地址 → 并行试连 → 进入 §6 选路。
- 名片是公网 IP 离开本机的**唯一途径**(用户主动复制);广播绝不含公网 IP。

## 4. 两通道模型(系统只认两种通道)

- **直连 DIRECT**:一切可直接建 QUIC 的地址。局域网 IP / 公网 IP / 名片带来的任何地址——**无差别**,不设"WAN 通道"概念。
- **中继 RELAY**:经 relay 转发,端到端加密,relay 只见密文。

用户心智只有"直连/经中继"两种;底下几个地址、什么网段,是软件自己的事。

## 5. 质量探测(阶梯式)

### 5.1 探测方法

- **带宽**:阶梯探测 64KB → 512KB → 4MB 三级计时,取最优稳定值。总开销 ~5MB/对设备/次,千兆 LAN 上 1-2s。
- **RTT**:QUIC Ping 3 次取中位(会话建立后)。
- **稳定性**:近 10 次探测丢包率。

### 5.2 时机纪律

- 首次建立会话:全量测(直连 + 中继各一轮)。
- 周期复测:5 分钟,只测当前通道 64KB 快检。
- 快检值掉 50% → 升级全量复测。
- 有活动传输 → 推迟到空闲。
- 质量探测**不进广播包**(广播保持 6 字段)。

### 5.3 记录

每设备一份通道记录:{地址, RTT, 估速, 稳定性, 时间戳}。

## 6. 智能选路(用户无感)

### 6.1 评分

score = RTT 分(50%) + 带宽分(35%) + 稳定性分(15%)
- RTT:<5ms=100, 50ms=60, 200ms=20, >500ms=0(线性插值)
- 带宽:>100Mbps=100, 10Mbps=50, <1Mbps=0(对数插值)
- 稳定性:丢包 0%=100, ≥10%=0

### 6.2 选路规则

1. 单通道可用 → 直接用。
2. 多通道:分数最高者,且**领先次优 ≥15 分才启用**(迟滞防横跳)。
3. 同分误差内:直连 > 中继 固定优先。
4. 地址探测超时 3 次 → 从记录摘除;下次会话建立时补测(地址可能回来)。

### 6.3 中途退化切换

- 触发:当前通道 RTT 连续 3 次复测翻倍,或传输失速 30s(复用现有看门狗信号)。
- 动作:后台在次优点建新 QUIC 会话 → 就绪 → 原子切换传输流 → 关旧通道。
- 断点续传天然支持跨通道(现有 job 断点机制)。
- 用户可见面:卡片标签悄悄变化,**不弹窗、不停传输**。
- 排障后门:卡片菜单"强制走中继"开关。

## 7. 连接状态机(显式全图)

```
不可见(未配对,探不到即消失)
  ↓ 发现
在线·待配对 ──配对成功──→ 在线·已配对(静默,无会话)
                            ↓ 用户点连接/浏览/推送/拖放
                          已连接
                            ↓ 网络断
                          重连中 ──成功──→ 已连接
                            └5 败──→ 在线·已配对(回落,可再手动点)
离线常驻卡:已配对+离线(信任表兜底,灰色)
```

**关键区分**:「在线」永远只是"广播可见",不代表已建会话。

## 7a. 配对生命周期全情况矩阵(新增)

### 7a.1 配对成功 → 自动连接

- PairResult ok 双方收尾后,**主动方立即发起业务会话**(被连方 accept 既有通道复用)——配对成功即"已连接",用户配完对直接可浏览/推送,无需再点一次"浏览"。
- 与 §8 连接记忆制衔接:这次自动连接视同"用户主动连接过"(配对是用户点的),此后断网自动重连适用。
- 失败兜底:自动连接失败(网络抖动)不报错,停留"在线·已配对",用户手动点浏览即恢复。

### 7a.2 单边移除信任 → TrustBroken 通知(新协议消息)

现状缺陷:A 移除 B 后 B 完全不知情(协议无信任撤销消息),B 卡片仍"已配对";B 下次连 A 走陌生人流程,体验为"我明明配过对,又让我输码?"。

- **即时通知**:A 移除时若会话还在,先发 `TrustBroken { reason }` 再断开(复用现有加密控制流,不新增明文面)。
- **握手兜底**:A 移除时会话已断(离线移除)→ B 下次连 A,A 在 Hello 阶段发现"B 认为我可信但我已不信任 B"→ 回 TrustBroken 并断开。
- B 收到 TrustBroken:清信任表 + 卡片即时变"待配对" + toast"对方已移除对你的信任"。
- 幂等:双方同时移除(竞态)时 TrustBroken 可能互发,收到时已删则忽略。
- 中继场景:名册互见不受影响(信任与发现是两层),B 仍能看到 A 在线,连接会被 TrustBroken 拒。

### 7a.3 重新配对流程(双盲对称,定案)

任何一边删了信任,重新发起连接时**双方都走完整同意门+配对码**(信任表还留着的一方也走):

- 3a 双方都删 → 纯陌生人,标准流程(现状已对)。
- 3b A 删 B 留;A 连 B → A 走陌生人流程;B 侧也走同意门,文案:"设备「X」请求重新配对(曾配对过)"。**不留方直接放行**——否则"A 删了 B,但 B 连 A 时 B 无感放行"会让 B 误以为一切正常。
- 3c B 留 A 删;B 连 A → 同 3b 对称。
- 3d TrustBroken 到达后双方都清 → 回 3a。
- 心智模型:重新配对 = 双方都重新确认,对称无特例。

### 7a.4 其他配对情况(查漏,现状已对)

- 配对中途取消/超时/拒绝:双方回滚,无残留。
- 配对码 3 错冷却 5 分钟(防暴力)。
- 已配对再发起配对:拒绝"已配对,如需重新配对请先移除信任"。
- 配对成功瞬间对端断网:PairResult ok 已落信任表,断连不影响信任,回"在线·已配对"。

### 7a.5 状态机增补边

```
在线·已配对 ──收到 TrustBroken──→ 在线·待配对(即时,toast 提示)
在线·已配对 ──配对成功自动连接──→ 已连接(§7a.1)
```



- **触发条件**:本软件运行期内用户主动连接过(点过连接/浏览/推送/拖放)。软件只守护"用户建立的连接",从不主动打扰——**不是一进软件发现对方就连接**。
- 未连接过的已配对设备:永远停在"在线·已配对",不自动建连。
- 节奏:指数退避 2s/4s/8s/16s,30s 封顶,每级最多 1 次,连续 5 败回落"在线·已配对"停止。
- 用户再点一次连接 = 重新开始一轮(记忆保留)。
- 重启软件 = 新会话,记忆清零,全部回静默。
- 与中继自愈的关系:会话级重连优先,失败轮到链路自愈;用户视角合一(都显示"重连中")。

## 9. 显示稳定

- 下线判定迟滞:15s + 连续探测无响应才变离线(防单包丢失闪"离线")。
- 排序:connected desc → online desc → name asc → fingerprint asc(指纹 tiebreaker 现状保持)。
- ~~刷新按钮~~ 已删除(§2):全通道自动化后无存在必要。

## 10. 卡片呈现改造

- 地址行 → **通道标签**:「直连 · 2ms」/「经中继 · 120ms」/「未知」。不再裸露 SocketAddr。
- 点击标签 → 通道面板:每地址一行(地址/RTT/估速/当前使用 ✓)。
- 状态徽章维持四态优先级:重连中 > 已连接 > 在线 > 离线。
- **卡片直推按钮(新增)**:已配对卡片的动作区在「浏览」旁增加「推送」按钮,点击直接打开 PushWizard 并**跳过步 1(选设备)**,进入步 2 选文件——目标设备已由卡片确定。前置条件同「浏览」:在线且已配对;离线置灰。顶部「推送文件」入口保留(从零选设备+选文件),两入口并存。
  - 动作区布局:浏览 + 推送 + ⏳ 角标 + ⋮ 菜单;⋮ 菜单内原有"推送文件…"项移除(卡片直推按钮取代,菜单减负)。

## 11. 本机侧呈现

- 设置页身份卡扩展:全部网卡地址列表(带接口名)+ 公网出口 + 中继地址。
- 「复制名片」按钮(§3)。
- 设备页 IP 徽章升级:显示首选地址,点击展开全部 + 复制名片入口。

## 12. 安全不变量(红线)

1. 指纹唯一信任根;地址/名字/短码都不是。
2. 广播包 6 字段永不扩;质量探测不进广播。
3. 公网 IP 只经名片(用户主动复制)离开本机;广播绝不含。
4. 名片公网行可勾选去掉(唯一暴露开关)。
5. fail-closed:一切验证失败静默丢弃;通道切换选中的新地址仍走 mTLS + 指纹钉扎(复用现有安全栈,不新增明文服务)。
6. 日志纪律:IP 不打日志,指纹只打前 8 hex,质量记录只打通道名 + 指标数值。

## 13. 三端分布

| 层 | 改动 |
|---|---|
| core | 地址枚举/名片生成与解析/通道记录/阶梯探测/评分选路/退化监测/状态机/连接记忆重连 |
| relay | 注册应答回报公网出口(一句字段,唯一改动) |
| PC 壳+UI | 名片/粘贴解析/通道标签/通道面板/重连徽章 |
| Android(FFI+UI) | 名片/标签/状态徽章同步;探测经 FFI DTO 暴露 |

## 14. 明确砍掉的设计(防复活)

| 项 | 理由 |
|---|---|
| 唤程码(v1) | 名片 + 两通道已覆盖其全部场景 |
| 配对前短码核对(v1) | 6 位配对码同意门已是完整核对机制,叠加即冗余摩擦 |
| WAN 一等通道(v2) | 罕见场景;地址无差别化后选路天然处理 |
| 64KB 单块抠门探测(v2) | 用户放宽消息预算;阶梯探测精度更好且不打满带宽 |
| 隐身禁出站探测(现状行为) | 逻辑不自洽(能被动看广播却不能主动问);修正为隐身只约束"被看见" |
| "刷新"按钮(现状) | 三通道全自动化后无存在必要;连同空状态引导一并移除 |

## 15. 验收要点(spec 级)

1. 名片复制 → 对方粘贴 → 解析出全部地址并试连,成功发现。
2. 多网卡机器名片含全部地址;VPN 默认路由不再遮蔽真实可用网段。
3. 双通道可用时选分高者;人为降级当前通道(如断网线),传输不停、标签静默切换。
4. 已配对设备启动后停留在"在线·已配对",无自动会话;用户连接过之后断网,2s 内出现"重连中",恢复后自动回"已连接"。
5. 5 次重连失败后回落"在线·已配对",不再重试;再点连接重新开始。
6. 下线迟滞:拔网线后 15s+ 才变"离线",期间单次探测失败不闪变。
7. 广播包抓包验证:仍为 6 字段,无任何 IP/质量信息。
8. 日志检查:无完整 IP、无完整指纹、无质量数据明文落盘。
9. 隐身语义修正:隐身中手动添加对方 IP → 探测照发、对方出现;对方探测我 → 仍无回应。
10. 刷新按钮已删:设备页无刷新入口;对端新开软件 ≤5s 自动出现,空状态文案为等待提示而非操作引导。
11. 配对成功自动连接:配完对双方卡片即"已连接",无需再点浏览;可直接开始推送/浏览。
12. 单边移除即时同步:A 移除 B(会话在)→ B 卡片 ≤1s 变"待配对" + toast;A 离线移除 → B 下次连 A 握手即被 TrustBroken 拒,卡片同步降级。
13. 双盲对称重配:单边移除后任一方发起连接,双侧同意门都出现,文案标注"曾配对过";输码成功双方信任表互写,自动连接。
14. 卡片直推:已配对卡片点「推送」→ PushWizard 直接进选文件步(无选设备步);顶部入口行为不变(完整两步)。
