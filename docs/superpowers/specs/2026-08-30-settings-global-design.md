# 设置页与全局基建定案(收尾批)

> 日期:2026-08-30
> 版本基线:v0.11.0
> 状态:已与用户逐项确认
> 关联:本批关闭 15 篇 D 表全部遗留分歧(D2/D7);并对传输域 spec 的通知表述做一致性修正。

## 0. 背景

四域梳理(设备页/传输域/浏览页)完成后的收尾批:设置页 7 卡逐卡过、全局基建分歧(D2/D7)、防火墙关切定向澄清。本批以"维持现状"为主基调——产品阶段不需要的复杂度一律不加。

## 1. 设置页:维持 7 卡单页

- 信息架构不变:共享区/下载目录/本机身份/信任设备/防火墙/中继/连接安全,单页滚动;不做分组导航、不做搜索(设置项 <20,YAGNI)。
- 新增项按已定案落位:
  - 本机身份卡 → ★名片扩展(域一定案:全部地址/公网出口/中继地址/复制名片)。
  - 连接安全卡 → ★并发任务数(域二定案:默认 3,可调 2-3 或合理范围)。
- 信任设备卡的"移除"与域一 TrustBroken 定案联动(移除即通知对端);权限修改入口维持在设备卡片下拉(此处只读展示不变)。

## 2. 防火墙:现状已够,不动

- 启动自检(缺规则 → toast 警告)+ 设置页体检(规则三态/本机 IP/三 profile)+ 一键放行(UAC)+ netsh 手动命令展示,覆盖主场景。
- 明确不做(评估后否决):
  - 运行中周期体检/防火墙变化监测——过度防御,真出问题走排障路径(打开日志)。
  - toast 带动作按钮一键修复——路径已短(去设置页两步)。
  - profile/虚拟网卡诊断深化——受众小,现状"宁可多提醒"策略够。
- 本机 IP 展示随域一名片定案升级(单选→全列表),在域一实现中一并落。

## 3. 全局基建定案

| # | 项 | 定案 |
|---|---|---|
| D2 | 设备列表过滤/置顶/分组 | **维持现状**(已连接>在线>名字序+离线常驻;设备数少够用) |
| D7 | 托盘(最小化/关闭到托盘) | **不做**——无常驻需求,关窗即退出(有任务拦截)维持 |
| — | 开机自启 | **不做**(与无托盘一致;要用手动开,行为可预期) |
| — | 完成通知系统级 | **仅应用内 toast**——修正传输域 spec §5"系统级可选"表述:不做 Windows 通知中心,与无托盘一致(窗口最小化仍在任务栏,toast 可见性够) |

## 4. 保持现状确认(零改动)

- 全事件驱动(设备/传输/共享推送,无轮询)。
- Toast 4 级 3s 自动消失。
- 失败一键重试(内存 lastRequest)+ 错误不泄露本机路径。
- 命令 15s 超时兜底;单实例聚焦;优雅关闭(Goodbye+落盘)。

## 5. 验收要点

1. 设置页仍为 7 卡单页;无分组导航/搜索框。
2. 设备页无过滤/置顶控件;离线常驻卡维持。
3. 无托盘图标、无开机自启项;关窗仍触发活动任务拦截。
4. 任务完成仅 toast;Windows 通知中心无 LocalTrans 通知。
5. 防火墙卡片行为与 v0.11.0 一致(无新增监测/按钮)。

## 6. 影响

- 15 篇 D 表全部关闭(D1-D12 均已定案)。
- 传输域 spec §5 的"系统级通知可选"按本批修正为"不做系统级";实现时以本 spec 为准。
