# Spec P2: 打磨·配对流程健壮性与体验（polish-pairing）

> 节奏位：第三段第 2 站。输入源：M1-M3 期间打磨池配对类记录 + 本 spec 梳理。
> 一句话：配对永远成功一次就过，失败了知道为什么、怎么办。

## 目标
配对全失败路径可控、可懂、可恢复。

## 范围
**做**：FR1-FR4。**不做**：协议变更（除已有 TrustBroken）。

## 功能需求
- **FR1 失败路径梳理**：枚举配对全部失败分支（对端拒绝/同意超时/错码 1-2 次/3 次冷却/码过期/连接断开/双方并发发起/重复配对已信任）——每支定义用户可见反馈与下一步引导。
- **FR2 错码反馈**：输错即时区分"码错(可重输 N 次)"与"已达上限进入冷却(倒计时可见)"；冷却期内发起方按钮态明确。
- **FR3 超时引导**：同意门/输码超时的文案给出可操作建议（对端在吗/网络可达吗），并保留"重试"直达。
- **FR4 并发与竞态**：双方同时点连接的双盲场景行为定义（一边胜出，另一边转为被连方）；配对中途断线的清理与重试。

## 验收标准
1. **配对失败矩阵场景**：上述全部分支逐条场景化断言（反馈文案+状态恢复+可重试）；
2. 双方并发发起场景通过；
3. 配对路径在 run-all 中以冷启动+失败矩阵双形态常驻。

## 依赖与顺序
依赖 V 段。打磨池配对类条目关闭。

## 风险
- 失败分支多而碎——先出分支表评审再动手（本 spec 的 writing-plan 第一个任务）。
