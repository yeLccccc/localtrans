# 传输页与任务状态管理设计(传输域重构)

> 日期:2026-08-30
> 版本基线:v0.11.0
> 状态:已与用户逐项确认(brainstorming 全部分歧定案)
> 来源:传输页功能树梳理中发现任务卡片状态管理结构性缺陷,用户提出"一个任务只一个卡片""任务与状态可追踪、清空列表后磁盘仍有历史、软件关闭也能从磁盘恢复",经排查确认根因后逐项定案。

## 0. 背景与根因

现状缺陷(代码核实):

1. **删除无主权仲裁**:`remove_transfer` 只做表 remove+可选删 parts,不检查任务状态、不通知引擎——active 任务删行后引擎还在传,事件再到达可能复活幽灵行;重启时 pending_jobs 扫描又把"删不掉的任务"带回来。
2. **多写者丢更新**:`transfer_update` 被 5+ 处调用,全靠"get_mut 克隆→改→insert 回"模式,锁在 await 点让出,并发改同一条后写覆盖前写——卡片数据错乱(done 累加异常)源于此。
3. **占位行→实件行替换竞态**:两套 ID(占位 u64::MAX 递减 / 真实 job_id),替换 remove+insert 非原子,4Hz 泵夹在中间会拍到"两条都在/都没有"。
4. **两份记录失联**:transfers.json(卡片表)与 .localtrans-parts/manifest.json(物理进度)互不相识;清列表后 parts 成孤儿,无 UI 可见可恢复;parts 被删则卡片续传必败。

## 1. 定案一:单卡片状态机(1 任务 1 卡片)

### 1.1 原则

- **1 任务 = 1 卡片**:占位行与实件行合一——占位只是卡片的 pending 态,ID 恒定(创建卡片时即定 job_id),不再有"删占位插实件"的替换操作,竞态源头消失。
- **单写者**:所有变更经状态机 `apply(event) → 新状态`;读改写在锁内完成不跨 await(或 actor 模型事件单线程 apply),消除丢更新。
- **删除 = 状态迁移**,不是 HashMap.remove。

### 1.2 卡片生命周期状态机

```
┌────────┐ 创建(下载/推送/接受)
│ pending │──────────────┐
└───┬────┘              │ 引擎 Started
    │ 排队超时60s         ▼
    ▼           ┌────────┐ Cancel/拒绝
┌─────────┐     │ active │──────────┐
│ failed  │◄────┴───┬────┘          ▼
└─────────┘  失速/   │ pause    ┌──────────┐
    ▲        JobFailed│         │cancelling│→引擎确认/5s超时→deleted
    │                 ▼         └──────────┘
    │            ┌────────┐
    └────────────┤paused  │
      续传失败    └───┬────┘
                    │ resume → active
终三态:done / failed / interrupted(计时冻结)
```

### 1.3 删除仲裁

- 终态任务:直接删行(走两级删除,见 §2.3)。
- 活动任务(pending/active/paused):先入 `cancelling` → 发 Cancel → 引擎回执或 5s 超时 → 删行+parts。
- 状态机之外的任务事件:丢弃 + warn 日志(不复活)。
- `clear_completed` 逐条走状态机删除路径,不绕过。

### 1.4 一致性保证

- 4Hz 泵只读快照不写;表签名含删除版本号,删除立即反映到前端。
- 多文件批次:一张父卡片,ID 为批次 ID;子文件状态在卡片内部视图(见 §4)。

## 2. 定案二:磁盘 manifest 唯一真相源

### 2.1 原则

- manifest(.localtrans-parts/{job}/manifest.json)是任务的唯一真相;卡片状态是它的投影,任何时刻可从磁盘全量重建。
- 软件关闭/崩溃/强杀后,重启 pending_jobs() 全量扫描 + manifest 元数据 → 完整卡片回归。

### 2.2 记录合一

- 卡片元数据(角色/对端指纹/方向/创建时间/起止时间戳/显示名/重试次数/取消原因)并入 manifest;transfers.json 降级为可丢弃的索引缓存(损坏可重建)。
- 状态迁移历史 append-only 记入 manifest(小日志)——"这个任务经历过什么"可回放。

### 2.3 两级删除

| 级别 | 动作 | 效果 |
|---|---|---|
| 移除视图(remove from view) | 删索引条目,manifest+parts 保留 | 卡片从列表消失;"历史记录"里随时找回、可续传 |
| 彻底删除(destroy) | 取消引擎任务 → 删 manifest+parts | 不可恢复(二次确认) |

- "清除已完成"语义 = 移除视图。
- 新入口**历史记录**:列出磁盘上全部 manifest(含已移除视图的孤儿),支持恢复视图/彻底删除/批量清理。

### 2.4 GC 策略

- 索引(transfers.json)150 条封顶不变。
- 磁盘:彻底删除时即删;历史记录手动清;**取消 7 天 mtime 盲删**——改为空间紧张时提示用户;唯一自动清理保留"位图全真孤儿"(完整性存疑)直接删。

## 3. 定案三:有限并发(D6)

- 全局同时活跃任务上限 **2-3**(默认 3,设置页可调)。
- 超出进队列:卡片显示"排队中·第 N 位";队首完成/失败自动出队下一个。
- 队列优先级:创建时间先来先服务;用户手动"立即传输"可插队(可选实现)。

## 4. 定案四:多文件任务统一父卡片+子展开(D10)

- 一批文件(推送多选/文件夹拉取)恒为**一张父卡片**(批次 ID),不再裂变 N 行。
- 父卡片展开显示子文件明细:各自状态/进度;失败子文件红标可单独重试。
- 父卡片整批操作:暂停/继续/取消/删除。
- 与单卡片状态机一致:父卡片一个状态机实例,子文件是卡片内部视图。
- 两方向(拉取/推送)形态统一,消除现状不一致。

## 5. 定案五:前端呈现(四项)

- **D9 对端显示**:接设备页别名体系(别名 > 广播名),指纹缩写退到 tooltip/小字。
- **D11 发送方双进度**:主数字 = 对端已确认量(remote_done);辅助显示已发量;差距 >20% 时提示"网络积压"。满格但对端未确认期间进度条显示"等待确认"态(条纹/降饱和),不提前变绿。
- **D12 列表组织**:活动优先(进行中+排队在前),历史(完成/失败/中断)折叠区;可按设备分组(可选实现)。
- **D8 完成通知**:拉取+推送全部完成时发应用内 toast 通知(2026-08-30 修订:不做系统级通知——与"不做托盘"决策一致,窗口最小化仍在任务栏,toast 可见性够;见 specs/2026-08-30-settings-global-design.md)。
- **刷新按钮**:删除(事件驱动;历史记录区打开时自动拉取磁盘)。

## 6. 安全与日志不变量(延续)

- manifest/索引不含对端敏感明文 beyond 现有(指纹 hex、文件名已在盘);日志仍只打指纹前 8 hex。
- 历史记录入口显示的磁盘文件名即本机磁盘文件名,无新暴露面。

## 7. 三端分布

| 层 | 改动 |
|---|---|
| core | manifest 元数据扩展+迁移;pending_jobs 重建含元数据;状态迁移历史;GC 策略改造;全局并发闸门+队列调度器 |
| PC 壳 | transfer 状态机 actor(单写者);remove_transfer 改两级删除+仲裁;cancelling 状态;父子任务 DTO |
| PC UI | 父卡片+子展开组件;双进度;别名;活动/历史分区;历史记录入口;删刷新 |
| Android(FFI+UI) | FFI 暴露新 DTO/命令;UI 同步(父卡片/双进度/历史) |

## 8. 明确砍掉/否决

| 项 | 理由 |
|---|---|
| 传输页保留刷新按钮 | 事件驱动+历史区自动拉,无必要 |
| 一行一文件形态 | 列表膨胀;与拉取方向不一致 |
| 7 天 mtime 盲删 parts | 静默丢用户数据;改为显式两级删除+手动清理 |
| 无限并发 | 带宽稀释;有限并发 2-3 定案 |

## 9. 验收要点

1. 传输中删除任务:卡片先变 cancelling,引擎停止后消失;不再出现幽灵行/复活。
2. 强杀进程后重启:全部任务带完整元数据(名字/对端/角色/时间)回归 interrupted,可一键续传。
3. 清除已完成后:历史记录入口仍可看到磁盘 manifest,可恢复视图或彻底删除;彻底删除后 parts 目录消失。
4. 多文件推送:全程一张父卡片,展开见子文件;整批取消有效。
5. 发送方进度:主数字与对端屏幕一致;积压时出现提示;终态不提前变绿。
6. 并发上限:同时活跃 ≤3,第 4 个起排队显示位次;队首完成自动出队。
7. 手动删除 parts 目录后重启:对应卡片显示"数据丢失"态而非可续传。
8. 列表:默认活动优先;历史折叠;对端显示别名。
9. 任务完成(拉取+推送)均有通知;传输页不在前台也收到。
