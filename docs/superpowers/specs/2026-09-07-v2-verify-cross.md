# Spec V2: 逐功能验证·三端×三网交叉矩阵（verify-cross）

> 节奏位：第二段第 2 站。依赖 V1 的场景设施。
> 一句话：功能单点都绿之后，验证组合与长稳——发版信心的最后一块。

## 目标
端×网交叉矩阵全绿 + 长稳通过。

## 范围
**做**：FR1-FR3。**不做**：新断言体系（复用 V1 场景设施）。

## 功能需求
- **FR1 交叉矩阵**：端={huss_pc, huss_laptop, huss_phone} 任取两两；网={直连, 隔离(名片兜底), 中继}；矩阵每格=发现→连接→双向传输→断线恢复断言。逐格执行出矩阵报告。
- **FR2 长稳场景**：≥1h 混合负载（并发多任务/暂停恢复/取消/秒传混合/中途 L2 重启一次），期间每分钟断言：无僵尸卡、并发槽无泄漏、内存无持续增长、日志无 ERROR 洪泛。
- **FR3 弱网注入**（隔离格用）：防火墙规则/限速制造丢包与高 RTT，断言自适应流控不崩、退化路径（M3b）按设计触发。

## 验收标准
1. 矩阵报告全绿（9 格）；
2. 长稳场景通过且证据（曲线/日志）归档；
3. 弱网格的降级行为符合 M3b 定案（迟滞/切换/兜底）。

## 依赖与顺序
依赖 V1。其后进入 P 段。

## 风险
- 手机格的长稳受 M2-FR6 影响——若退化根因未彻底关，本站会暴露（这正是本站目的）；
- 弱网注入的规则清理失败会污染后续场景——规则增删必须 finally 还原。
