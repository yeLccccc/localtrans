## 1. 概述

lan-drop 是一个 **Windows 绿色便携版** 点对点文件互传工具:两台(或多台)电脑各运行一个实例,每个实例**既是服务端也是客户端**,通过 QUIC(TLS 1.3 强制加密)在局域网内高速互传文件;可选部署独立中继服务实现**跨局域网**通信。

**核心目标:**
1. 所有传输数据强制加密,中继也无法解密内容
2. 极致带宽利用:多流并发 + 自适应调参,千兆有线打满,混合环境(WiFi)自动爬升
3. 局域网自动发现 + 应用层隐身
4. 首次配对(验证码)+ 信任设备的握手模型,防中间人
5. 共享区(可配置多个文件夹)对已配对设备可见,支持对方自行浏览与下载,以及主动推送
6. 大文件分块传输与断点续传
7. 单 exe 绿色便携,数据随身走

**非目标(明确不做):**
- 公网 NAT 打洞直连(跨网一律走中继;打洞留作未来可选优化)
- 移动端 / macOS / Linux GUI 客户端(中继服务端支持 Linux)
- 传输历史云同步、账号体系
- 中文之外的多语言(架构预留 i18n,首版仅中文)

## 3. 总体架构

### 3.1 二进制形态

同一 Cargo workspace,两个发布产物:

| 产物 | 形态 | 说明 |
|------|------|------|
| `lan-drop.exe` | Windows GUI(Tauri 2 + Vue 3) | 客户端,双击即用 |
| `landrop-relay` | 无界面服务端(Rust,Windows/Linux) | 部署到有公网 IP 的 VPS |

### 3.2 客户端进程模型

单 Tauri 进程;Rust 侧一个 tokio runtime 承载全部网络与磁盘任务;前端**只**通过 Tauri command(请求-响应)与 event(推送)通信,永不直接碰网络。

```
┌─────────────────────────────────────────────────┐
│  Tauri 窗口(Vue 3)                               │
│  设备│传输│浏览│设置 + 托盘                        │
└───────────────────┬─────────────────────────────┘
                    │ command / event(进程内 IPC)
┌───────────────────┴─────────────────────────────┐
│  Rust 核心(六模块)                                │
│  identity │ discovery │ session                  │
│  transfer │ share     │ store                    │
│  全部业务流量走 QUIC(quinn,TLS 1.3 强制)          │
└─────────────────────────────────────────────────┘
```

### 3.3 模块职责

| 模块 | 职责 | 关键依赖 |
|------|------|----------|
| `identity` | 设备密钥对、自签证书、指纹、信任列表逻辑 | rcgen、ed25519-dalek、rustls |
| `discovery` | UDP 广播 presence/probe、签名验签、隐身开关、设备列表缓存 | tokio UDP |
| `session` | QUIC endpoint、连接生命周期、多会话管理、配对状态机 | quinn |
| `transfer` | 分块、并发 stream 调度、自适应、清单与断点续传、块校验 | quinn streams |
| `share` | 共享区(多文件夹)、虚拟目录树、路径安全、推送接收策略 | — |
| `store` | 配置/信任/清单持久化(JSON 文件) | serde |

### 3.4 端口与目录

- 发现:UDP `47600`(局域网广播)
- 传输:UDP `47601`(QUIC)
- 中继:UDP `47602`(公网,landrop-relay 监听)

便携目录布局(exe 同级):

```
lan-drop.exe
data\
  config.json          # 端口、下载目录、隐身、中继配置等
  identity.key         # Ed25519 私钥(首次启动生成,永不更换)
  cert.der             # 自签证书
  trusted_peers.json   # 信任设备:指纹+名称+权限+配对时间
  transfers\           # 任务队列元数据(重启恢复队列用);块清单随分块数据在 .landrop-parts
downloads\             # 默认下载目录(可改)
.landrop-parts\        # 跟随下载目录:分块 *.part 数据
```

**便携性对策:**
- 首次监听 UDP 时 Windows 弹标准防火墙放行弹窗;设置页提供"一键添加防火墙规则"(netsh advfirewall,UAC 提权),因 exe 换路径后旧规则失效
- WebView2 运行时缺失时启动检测并提示(不自动安装,保持绿色;Win10/11 基本自带)
- exe 路径互斥锁防同目录双开

## 4. 设备发现与隐身

载体:UDP 广播(47600),JSON 包 + Ed25519 签名。广播明文可见但**零敏感信息、零授权能力**,一切实际操作必须走第 5 节加密握手。

### 4.1 消息类型

```
presence    → 255.255.255.255  "我叫XX,指纹yy,传输端口47601"
probe       → 255.255.255.255  "谁在线?回我一声"
probe-resp  → 单播回探测者      "我在,我叫XX,指纹yy"
```

包字段:`{ v, type, name, fingerprint, quic_port, ts, nonce, sig }`,签名覆盖除 sig 外全部字段(规范化序列化后签名)。

- `fingerprint = SHA-256(cert DER)`,即设备身份证号
- `ts` ± 30 秒窗口外丢弃 + `nonce` 缓存去重 → 防重放

### 4.2 节奏与生命周期

- 启动连发 3 个 presence,之后每 5 秒一次(带随机抖动)
- 打开设备列表/点刷新时发一次 probe(隐身设备靠这个发现别人)
- 设备条目 15 秒无更新 → 标记离线并移除

### 4.3 隐身模式

| 行为 | 正常 | 隐身 |
|------|------|------|
| 周期 presence | ✅ | ❌ |
| 回应 probe | ✅ | ❌(别人列表没有我) |
| 主动 probe 扫描 | ✅ | ✅(对方仅看到一个无名 IP 询问,应用层不显示) |
| 接受连接 | 按信任规则 | 按信任规则(隐身≠拒绝;手动 IP 直连与配对照常) |

设备列表页提供"通过 IP:端口 手动添加"入口。

### 4.4 中继发现(跨网)

见第 7 节。客户端把中继名录返回的签名 presence 与局域网广播结果**按指纹去重合并**;同设备双通道可见时优先直连。

## 5. 身份、配对与加密握手

### 5.1 设备身份

- 首次启动生成 **Ed25519 密钥对**(`data\identity.key`),永不再生成
- 以其签发**自签名证书**(rcgen),证书公钥 = 身份公钥
- 指纹 = SHA-256(cert DER),UI 展示为 8 位短码(如 `A3F2-91BC`)

### 5.2 连接与校验

- 每次连接 QUIC/TLS 1.3(rustls),证书为自签;**不使用系统 CA 体系**,只认指纹
- 对端证书指纹 ∈ 信任列表 → 静默建立加密通道
- **不在信任列表 = 一律触发配对**(无论发现包是否声明过该指纹 —— 发现包指纹仅作 UI 展示参考,不构成任何信任依据,防自签 presence 诱骗)

### 5.3 首次配对(双向 SAS 核对,防中间人)

1. A 发起连接,B 出示证书,A 尚未信任 → 进入配对
2. 双方各自从**本端 TLS 1.3 key exporter**(通道绑定)派生 6 位验证码:
   `code = HKDF(exporter_secret, info = 双方指纹)`(ZRTP 式 SAS 短认证串)
   — 只有真正端到端直连(无中间人)的双方,两条派生码才相同
3. **双向核对**:A、B 屏幕**各自显示**自己的码;用户通过任意带外渠道(口头/电话/聊天)把对方的码告诉本方,各自输入,**各自本地校验**
   - 单向"B 显示、A 输入、B 校验"是不安全的:中间人把用户口述的码原样转发即可通过 B 的校验
   - 双向核对下,中间人两侧派生码必不同,任一侧输入即当场失败
4. 双侧都通过 → 双方互存指纹 + 默认权限到 `trusted_peers.json`,连接建立
5. 验证码任一侧连错 3 次 → 拒绝并冷却该设备 5 分钟(防爆破)

### 5.4 连接确认策略

- 已信任设备发起连接:静默建立
- 未信任设备来连:B 弹配对请求窗(显示本端验证码 + 输入对方验证码,可拒绝;对应 5.3 双向核对)
- 已信任设备推送文件:按该设备的推送权限(见 8.3)

加密套件:TLS 1.3 默认(X25519 + AES-256-GCM / ChaCha20-Poly1305),AES-NI 硬件加速,加密不构成带宽瓶颈。

## 6. 传输引擎

### 6.1 分块与清单

- 文件切 **4 MiB 固定块**(末块可小),每块 SHA-256
- 接收方 `<下载目录>\.landrop-parts\<任务ID>\` 存:
  - `manifest.json`:文件名、大小、chunk_size、总块数、每块哈希、完成位图
  - `<任务ID>.part`:按块偏移稀疏 pwrite,完成整文件后改名落定 + 可选整文件校验
- 块是原子单位:收完→验哈希→落盘;失败块不占位

### 6.2 并发模型

```
              ┌── stream 1 ──→ 块#0, #4, #8 ...
  读取器 ──→  ├── stream 2 ──→ 块#1, #5, #9 ...    ──→ QUIC(TLS 1.3)
 (缓冲池)     ├── stream N ──→ 块#3, #7, ...
```

- 多条 QUIC stream 并行拉块,流间无队头阻塞
- **自适应流数**:4 条起步,每 500ms 测总吞吐;吞吐仍涨且丢包低 → +1(上限 16);增长无增益或丢包 >5% → 停止并回落。千兆有线 4~6 条即满,WiFi 自动爬升
- **内存硬上限**:全局缓冲池 32 × 4 MiB = 128 MiB,发满即背压
- 磁盘:读侧预取、写侧乱序按偏移落盘,完成改名

### 6.3 任务调度(每会话)

- 传输队列;同时活跃任务 ≤ 3(大文件独占权重,小文件捎带)
- **小文件(≤1 MiB)成批流水**:不切块,一条流连发,防千张照片逐个开销
- 暂停/继续/取消;拉取与推送队列独立互不阻塞

### 6.4 断点续传

1. 连接断开 → 任务**冻结**(非失败),清单已持久化
2. 重连后接收方发完成位图给发送方对账
3. 只补缺失块;乱序到达的已完成块不重传
4. 程序重启同理;重启后队列恢复(可确认)

### 6.5 块校验失败

NACK 重请求;同块连错 3 次 → 任务转失败并保留清单(可重试)。

### 6.6 会话内协议(控制流 + 数据流)

- 每连接首个双向 stream = **控制流**(JSON 消息:`LIST` / `META` / `FETCH` / `OFFER` / `ACCEPT` / `PAIR_CODE` / `PAUSE` / `CANCEL` / `BITMAP` …)
- 数据流:每块一条单向 stream,头部定长 `{job_id, chunk_index}`,收完即关
- 控制流永不传大数据,保证指令低延迟

## 7. 中继服务(landrop-relay)

单二进制 + `config.toml`,无界面;监听公网 UDP 47602(QUIC)。

```toml
listen_port = 47602
psk = "长随机字符串"             # 准入密钥,客户端必须持有
max_clients = 50
max_circuits_per_device = 4
per_circuit_bandwidth = 0        # 字节/秒,0=不限(小水管 VPS 保护)
```

### 7.1 接入认证(三层)

1. **mTLS**:中继持自己的证书;客户端出示设备证书作 TLS 客户端证书 → 中继密码学确认"谁"在线
2. TLS 建立后首帧发 **PSK**,不符即断(防陌生人蹭 VPS)
3. 客户端首连中继记下中继证书指纹(**TOFU**),防域名劫持指向假中继

### 7.2 设备名录(跨网发现)

- 客户端定期向中继登记第 4 节同款**签名 presence**(中继无法伪造)
- `LIST` 查询返回全部在线设备签名 presence;客户端与局域网结果按指纹去重合并
- 隐身 = 不登记,但仍可 LIST 与主动 CONNECT

### 7.3 数据转发(电路模型)

```
A ═QUIC═ relay ═QUIC═ B       外层:两条到中继的加密隧道
   └── circuit#7 ──────┘      中继按电路 ID 搬运字节
     内层:A↔B 端到端 QUIC 握手(证书/配对/验证码全照常)
```

- A 发 `CONNECT{B 指纹}` → 中继在两条隧道间搭电路,纯字节转发;一条隧道内以 QUIC stream 复用多条电路
- **内层连接关闭拥塞控制**(自定义 quinn 拥塞控制器:大固定窗口),由外层隧道统一调度,避免双层 CC 争抢退化
- 限速(若配置)在电路层令牌桶执行

### 7.4 中继可见性(诚实声明)

可见:设备名、指纹、IP、流量字节数、连接时间。**不可见**:文件内容、文件名、清单(全在内层端到端加密内)。

### 7.5 故障与恢复

中继重启 → 客户端指数退避自动重连、重新登记;电路死亡 → 端到端会话断 → 传输任务冻结走 6.4 断点续传,清单一块不丢。中继不可达 → 客户端降级纯局域网模式并标黄提示。

## 8. 共享区、权限与推送

### 8.1 共享区

- 设置页添加**多个文件夹**,各起别名(如"电影""工作文档"),对已配对设备按分类展示
- 未配对设备**看不到任何共享区**
- 目录变更不做实时推送,列表页手动刷新(YAGNI)

### 8.2 路径安全(防目录穿越)

- 请求仅可引用 `共享区ID + 相对路径`
- 服务端 canonicalize 后**强制校验仍在该共享区根内**,否则拒绝
- Windows 符号链接 / junction(重解析点)默认不跟随

### 8.3 每设备权限(存 trusted_peers.json)

| 权限 | 默认 | 说明 |
|------|------|------|
| 浏览共享区 | 开 | 看目录列表 |
| 下载文件 | 开 | 自行拉取 |
| 推送文件 | 每次询问 | 弹窗确认;可改"自动接收"或"拒绝" |

### 8.4 推送流程

```
A 选文件 → OFFER{文件名,大小,总哈希} → B 弹窗[接收/拒绝/另存]
                                  └→ ACCEPT → 进传输队列,完成后 B 收通知
```

拖拽文件到设备卡片 = 发起推送。拉取的文件进**接收方下载目录**(对方共享区只是源,不自动写入);用户可把下载目录设为共享区之一自由组合。

## 10. 错误处理

| 故障 | 行为 |
|------|------|
| 连接断开 | 任务冻结 → 指数退避自动重连 → 清单续传,UI 全程可见 |
| 验证码错 3 次 | 拒绝配对并冷却该设备 5 分钟 |
| 磁盘写满 | 任务暂停 + 通知,清理后可续 |
| 块校验连错 3 次 | 任务转失败,保留清单可重试 |
| 中继不可达 | 降级纯局域网,状态卡片标黄 |
| 防火墙拦截入站 | 检测到入站不通 → 一键放行按钮(UAC) |
| 程序崩溃/重启 | 清单在磁盘,重启后恢复队列询问 |

原则:用户永远看到"发生了什么 + 能怎么办"。

## 11. 测试策略

- **单元测试(Rust)**:分块/清单读写、路径穿越用例(`..`、绝对路径、junction 逃逸)、SAS 派生一致性、发现包签名/验签/防重放、配置存取往返
- **集成测试**:本机回环双实例全流程 —— 发现→配对→互拉互推→**传输中途强杀进程验证续传**→隐身→权限开关→中继电路转发
- **吞吐基准**:合成 1 GB 文件回环 + 真实双机千兆有线,对标 iperf3 基线 **≥ 90%**(不达标调流数策略)
- **安全用例**:中间人模拟(伪造证书 → SAS 必不匹配)、重放发现包、未签名广播、目录穿越

## 13. 实施阶段

- **阶段一(主体)**:workspace 搭建 → identity/store → discovery(含隐身)→ session+配对 → transfer(分块/并发/自适应/续传)→ share+权限 → Vue UI → 便携打包与防火墙体验
- **阶段二(中继)**:landrop-relay(mTLS/PSK/名录/电路)→ 客户端中继接入与名录合并 → 隧道模式内层 CC 定制 → 跨网集成测试
- 阶段一完成即可日常使用;阶段二独立追加,不动阶段一协议。
