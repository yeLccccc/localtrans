# Spec P3: 打磨·交互流程与前端细节（polish-flows）

> 节奏位：第三段第 3 站。输入源：打磨池"流程不合理"类记录（收集器型 spec）。
> 一句话：把实际用起来别扭的地方逐个捋顺。

## 目标
消化打磨池流程类条目；交互心智模型三端一致。

## 范围
**做**：FR1-FR5（以届时打磨池实际内容为准，以下为已知项）。**不做**：新功能。

## 功能需求（已知项，writing-plan 时以池为准）
- **FR1 接收流程**：另存路径选择的顺延/记忆；接收中切目录的一致性；拒绝后的再推路径。
- **FR2 删除与历史心智**：两级删除文案统一（移除=可找回/彻底删除=不可恢复）；磁盘历史入口可见性；"清除已完成"语义=移除视图的提示明确。
- **FR3 信任列表缓存滞后**：配对/移除后设置页即时刷新（本周实证的缓存问题）。
- **FR4 重复设备条目**：手机换身份后旧条目清理策略（离线超时归档/合并按指纹）。
- **FR5 失败重试心智**：重试入口与参数记忆的一致性（重启后 lastRequest 语义）。

## 验收标准
1. 打磨池流程类条目清零（逐条指向提交）；
2. 每项改动有对应场景断言或截图目检；
3. 三端交互对照清单复核。

## 依赖与顺序
依赖 V 段。与 P4 可并行（不同泳道）。

## 风险
- 池内容不可预知——本 spec 允许在 writing-plan 阶段按池裁剪/增删 FR。
