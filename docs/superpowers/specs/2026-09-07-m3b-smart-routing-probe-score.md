# Spec M3b: 智能选路·探测与评分（probe-score）

> 里程碑：M3 第 2 段。依赖 M3a 的地址地基。
> 一句话：知道每条路有多好，自动走最好的那条，坏了无声换路。

## 目标
通道质量探测、评分选路、中途退化切换，全程用户无感。

## 范围
**做**：FR1-FR5。**不做**：任何 UI（M3c）；广播包改动（质量数据不进广播——设计红线）。

## 功能需求
- **FR1 通道记录**：每设备一份 `[{地址, RTT, 估速, 稳定性(近10次丢包), 时间戳}]`，内存态+会话级生命周期。
- **FR2 阶梯探测**：带宽 64KB→512KB→4MB 三级计时取稳态（总开销 ~5MB/对设备/次）；RTT=QUIC Ping×3 取中位。时机纪律：首次建会话全量（直连各地址+中继各一轮）；5min 周期快检（仅当前通道 64KB）；快检掉 50% 升级全量；有活动传输推迟到空闲。
- **FR3 评分与选路**：`score = RTT(50%)+带宽(35%)+稳定(15%)`（插值表按 16 篇 §3.1）；多通道取最高且**领先次优 ≥15 分才启用**（迟滞防横跳）；同分误差内直连>中继固定优先；地址探测超时 3 次摘除（下次会话补测）。接入点：connect 命令的目标选择。
- **FR4 退化切换**：触发=当前通道 RTT 连续 3 次复测翻倍 或 传输失速 30s（复用既有看门狗信号）；动作=次优点后台建新 QUIC 会话→就绪→**原子切换传输流**→关旧通道；断点续传天然跨通道；不弹窗不停传输。
- **FR5 Android 对齐**：探测经 FFI DTO 暴露（与 PC 同源 core 逻辑）。

## 验收标准
1. 双通道模拟（直连+中继）场景：评分择优正确、强制切到次优仍可用；
2. 退化切换场景：传输中制造劣化（限速/丢包注入）→切换完成→字节核对→传输不断；
3. 迟滞单测：49:51 分不切换；
4. 探测时机单测：活动传输期间不探测。

## 依赖与顺序
依赖 M3a。M3c 依赖本 spec 的通道数据。

## 风险
- 探测流量扰民——设计红线：不打满带宽（4MB 上限已定）、不进广播；
- 切换原子性——新会话未就绪旧通道死亡的中断窗口：允许短暂 interrupted，断点续传兜底。
