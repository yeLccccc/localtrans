# 16 通道质量管理与智能选路

> 2026-08-30 定案(来源:specs/2026-08-30-device-identity-network-design.md §4-§6)。**整篇为目标设计,尚未实现**。
> 解决的问题:①多地址可达时(局域网+中继,名片带来多地址)不知道哪条路好;②网络切换(WiFi↔热点、跨网段漂移)时连接僵死在坏通道;③用户看不懂卡片上的裸 SocketAddr。

## 1. 两通道模型(系统只认两种)

| 通道 | 定义 | 备注 |
|---|---|---|
| **直连 DIRECT** | 一切可直接建 QUIC 的地址 | 局域网 IP / 公网 IP / 名片带来的任何地址——**无差别**,不设"WAN 通道"概念 |
| **中继 RELAY** | 经 relay 转发 | 端到端加密,relay 只见密文 |

用户心智只有"直连/经中继"两种;底下几个地址、什么网段,是软件自己的事。

设计演化记录:v2 曾把"公网直连"设计为一等通道,后砍掉——家宽 NAT 无映射是常态,真公网直连是少数派场景;能直连的地址进名片后与局域网地址同待遇参与试连,选路只看分数不看通道姓什么。省掉整条"WAN 安全专节"。

## 2. 质量探测(阶梯式)

### 2.1 探测方法

- **带宽**:阶梯探测 64KB → 512KB → 4MB 三级计时,取最优稳定值。总开销 ~5MB/对设备/次,千兆 LAN 上 1-2s。4MB 足以穿透 QUIC 慢启动看到稳态速率。
- **RTT**:QUIC Ping 3 次取中位(会话建立后)。
- **稳定性**:近 10 次探测丢包率。

### 2.2 时机纪律

- 首次建立会话:全量测(直连 + 中继各一轮)。
- 周期复测:5 分钟,只测当前通道 64KB 快检。
- 快检值掉 50% → 升级全量复测。
- 有活动传输 → 推迟到空闲。
- **质量探测不进广播包**(广播保持 6 字段,见 02 篇)。

### 2.3 通道记录

每设备一份:`{地址, RTT, 估速, 稳定性, 时间戳}`。

## 3. 智能选路(用户无感)

### 3.1 评分

```
score = RTT 分(50%) + 带宽分(35%) + 稳定性分(15%)
RTT:  <5ms=100, 50ms=60, 200ms=20, >500ms=0(线性插值)
带宽: >100Mbps=100, 10Mbps=50, <1Mbps=0(对数插值)
稳定: 丢包 0%=100, ≥10%=0
```

### 3.2 选路规则

1. 单通道可用 → 直接用(无决策)。
2. 多通道:分数最高者,且**领先次优 ≥15 分才启用**(迟滞防 49:51 横跳)。
3. 同分误差内:直连 > 中继 固定优先。
4. 地址探测超时 3 次 → 从记录摘除;下次会话建立时补测(地址可能回来)。

### 3.3 中途退化切换

- 触发:当前通道 RTT 连续 3 次复测翻倍,或传输失速 30s(复用现有看门狗信号)。
- 动作:后台在次优点建新 QUIC 会话 → 就绪 → **原子切换传输流** → 关旧通道。
- 断点续传天然支持跨通道(现有 job 断点机制)。
- 用户可见面:卡片标签悄悄变化,不弹窗、不停传输。
- 排障后门:卡片菜单"强制走中继"开关。

## 4. 本机地址感知

- **全列表**:枚举全部网卡地址(带接口名/网段标注)——替代 `primary_local_ip` 单选(UDP connect 8.8.8.8 只选默认路由,VPN 场景给出错误网段)。
- **公网出口**:经中继问询回报(relay 注册应答回一句"我看到的你的公网出口"),零外部探测;中继不在场则无此信息,名片不带公网行(不造假希望)。
- 名片生成即用此列表(见 02 篇 §4a)。

## 5. 呈现

```
卡片地址行 → 通道标签:
  「直连 · 2ms」(绿)      ← 不区分局域网/公网,对用户都是直连
  「经中继 · 120ms」       ← 显示总 RTT
  「未知」(离线常驻卡)

点击标签 → 通道面板(每地址一行):
  192.168.1.5    2ms    ~940Mbps  ✓ 当前使用
  经 relay      120ms   ~85Mbps
```

## 6. 三端分布

| 层 | 改动 |
|---|---|
| core | 通道记录/阶梯探测/评分选路/退化监测;地址枚举与名片生成解析 |
| relay | 注册应答回报公网出口(一句字段,唯一改动) |
| PC 壳+UI | 通道标签/通道面板/静默切换;名片复制入口 |
| Android(FFI+UI) | 同 PC;探测经 FFI DTO 暴露 |

## 7. 设计取舍

- 4MB 阶梯而非满速打流:精度够区分量级(LAN vs 中继),不扰民;用户已放宽消息预算,但"不打满带宽"仍是底线。
- 探测只在会话建立/复测触发,不进广播:广播包是全网可见的,质量数据是双方私事。
- 迟滞 ≥15 分:防两条相近通道来回横跳,切换本身有成本(新会话建立)。
- 带宽估算精度有限(单/少块计时受突发噪声):目标是选路决策,不是测速报告。
