# 02 设备发现(UDP 广播)

> 源码:`crates/localtrans-core/src/discovery.rs`(1528 行)。
> 2026-08-30 设计更新(来源:docs/superpowers/specs/2026-08-30-device-identity-network-design.md):隐身语义修正、名片打包、删刷新按钮、广播静默期。标〔2026-08-30 定案〕的段落为目标设计,尚未实现。

## 1. 设计目标

- 同一局域网内零配置自动发现:新设备上线互推 presence,几分钟内全网可见。
- **对称发现**:任何一方发一次探测,双方设备列表都出现对方(修复跨网段单边可见)。
- 跨网段(广播不可达)场景靠单播重探 + 持久化目标表兜底。
- 隐身模式:能看别人、不被别人看到。
- **发现通道四层**(〔2026-08-30 定案〕整理):同网广播(零操作)→ 中结名册(跨网自动)→ **名片打包**(跨网人工传递,新增)→ 手动加 IP(兜底)。前三层全自动/半自动,第四层降级为最后手段。

## 2. 协议设计

### 2.1 传输与端口

- **裸 UDP**(非 mDNS),`socket2` 创建,bind 前设 `SO_REUSEADDR + SO_BROADCAST`。
- 监听 `0.0.0.0:47600`(可配 `discovery_port`),广播目标 `255.255.255.255:47600`。
- **专用 OS 线程 + 阻塞 std socket**(非 tokio):Windows 下 tokio UDP recv 存在挂起冻结 runtime 的缺陷;发现层是低速率控制面,阻塞线程规避(L569-574 注释)。对外接口仍是 tokio channel。

### 2.2 包格式(DiscoveryPacket,L29-40)

```
wire = JSON字节 ‖ 64字节 Ed25519 签名
JSON: { v:1, kind, name, fingerprint:[u8;32], pubkey:[u8;32], quic_port:u16, ts_ms:u64, nonce:[u8;12] }
kind: "presence"(周期广播) / "probe"(探测请求) / "probe_resp"(探测应答)
```

`verify_and_parse`(L120-169)严格顺序:
1. **先验签**(失败不消耗重放槽位,防 nonce 抢注 DoS);
2. 时间戳 ±10 分钟窗口(`CLOCK_SKEW_TOLERANCE_MS`,兼容未对时机器——真机曾因日期差 2 天互不可见);
3. nonce 查重。

### 2.3 防重放(ReplayGuard,L58-101)

- `HashMap<nonce, ts>`,容量 4096。
- `check_nonce`:先 retain 清窗口外旧 nonce → 查重(重复=Replay 错)→ 容量满返回 Overflow 拒新条目(防无界膨胀)。

### 2.4 发送节奏

| 机制 | 周期 | 说明 |
|---|---|---|
| 启动 burst | 3 连发 | 立即宣告在场;SetName 同样 burst |
| 周期 presence | 5s ± 1s 抖动 | 随机抖动防同网段同步风暴 |
| 周期重探 | 每目标 8s | 只对 probe_targets 表内地址单播 |
| 读超时 | 250ms | 线程主循环 recv_from 超时,驱动三个时间节拍 |
| 设备过期 | 15s(`offline_secs`) | 独立 1s 节拍 retain,超时删除并发布 |
| **静默期拉长**〔定案未实现〕 | 5s→15s | 网络无对端活跃时拉长广播间隔,检测到对端活跃恢复 5s——控制消息数量的同时保持发现灵敏度 |

### 2.5 在线判定与设备表

- 设备表 `HashMap<fingerprint, DeviceInfo>`;**presence/probe/probe_resp 三种包都入表**(对称发现)。
- 连接地址 = **包内 quic_port(47601)+ 源 IP**(曾误用发现端口 47600 导致连接超时)。
- 设备列表经 `tokio::sync::watch` 广播(按 name 排序),壳层 watch 后 merge 中继名册发前端。

### 2.6 身份冲突检测(L802-811)

收到带**本机指纹**的包:nonce 在 own_nonces 滑动窗(128 条)内 = 自己的广播回环,忽略;不在 = 另一台机器复制了本机 data/ 身份文件 → warn 身份冲突。

## 3. probe_targets.json(跨网段保活)

- 表:`Vec<SocketAddr>` 重探目标,上限 8 个(`MAX_PROBE_TARGETS`,超出随机淘汰)。
- 单目标连续 10 次探测无回应(~80s)淘汰。
- **落盘时机**:新地址入表、失联淘汰时写 `data/probe_targets.json`(pretty JSON);启动恢复并立即开探 —— 解决重启后互相"失忆"。
- 文件损坏按空集处理,不阻断启动。

## 4. 隐身模式(hidden)

**语义〔2026-08-30 定案,含一处对现状的修正〕**:隐身只约束"被看见",不约束"我想看别人"。

- 被看见面(维持现状):跳过启动 burst、周期 presence;收到 probe **非隐身才回** probe_resp;中继 Register.hidden=true → 名册剔除 + Punch 统一"不可达"(见 06/07 篇)。
- **出站探测放行(修正项,未实现)**:现状把 ProbeNow/单播探测/重探发包也门控了(隐身时全部跳过),逻辑不自洽——"能被动看别人的广播,却不能主动问"。目标设计:隐身期间我主动发探测照发(点发现别人、手动添加对方、周期重探均不受隐身限制)。探测是定向单播,只发给明确目标,不构成"暴露自己"。
- 收包路径从不门控(能看别人),现状已符合。

## 4a. 名片打包〔2026-08-30 定案,未实现〕

跨网/隔离场景的主发现通道,替代"人肉传单个 IP":

- **内容**:名字 + 短码 + 全部本机地址(多网卡全列)+ 公网出口行(经中继问询所得,有则带,用户可勾选去掉,默认带)+ 中继地址行(配了中继则带)。
- **复制**:一键复制结构化文本,45s 自清剪贴板(沿用 A7)。
- **使用**:对方在手动添加框粘贴名片全文(也接受裸 IP,兼容旧用法)→ 解析全部地址 → 并行试连 → 进入通道选路(见 16 篇)。
- **安全定位**:名片是公网 IP 离开本机的唯一途径(用户主动复制);广播包绝不含公网 IP。
- 与唤程码的关系:曾设计"唤程码"(一次性短凭证唤程),已砍——名片 + 两通道覆盖其全部场景,不再有此概念。

## 5. 命令通道(DiscoveryCmd,mpsc 容量 8)

| 命令 | 行为 |
|---|---|
| `ProbeNow` | 立即广播 probe(〔定案〕隐身时**不再跳过**——出站探测放行,见 §4;〔定案未实现〕前端刷新按钮已删,此命令保留为壳层内部能力) |
| `ProbeAddr(SocketAddr)` | 单播探测并加入重探表(〔定案〕隐身时放行) |
| `SetName(String)` | 空名拒绝;更新出站包名 + burst presence + 单播通知重探目标(对端无需等重启即见新名) |

**刷新按钮已删〔2026-08-30 定案,未实现〕**:三通道全自动化(同网 5s 周期广播+启动 3 连发 / 跨网重探表 8s 自动补探 / 中结名册推送制),不存在需要手动刷新的窗口;PC 设备页刷新按钮与 Android 对应入口移除,空状态文案改为"等待网络中的设备出现(通常几秒内)"。

## 6. 线程模型与句柄

- 单线程 "localtrans-discovery":循环 = 非阻塞 try_recv 命令 → 250ms 超时 recv_from → 周期节拍(presence/重探/过期)。
- `DiscoveryHandle`:`devices: watch::Receiver<Vec<DeviceInfo>>`、`cmd: mpsc::Sender`、`shutdown: mpsc::Sender`;**Drop 置停标志 + join**(防线程泄漏)。

## 7. 壳层接入

- PC:main.rs `discovery::spawn(DiscoveryConfig{bind_port, hidden, name, quic_port, fingerprint, data_dir})`;设备 watch → merge(本地+名册+connected+别名+信任)→ emit `device-list`;手动添加设备 = `add_manual_device(IP[:port])` → ProbeAddr → 5s 后 emit `manual-probe-result`。
- Android(FFI):同 spawn;`probe_addr` 只收 IP 自动补 47600;devices() 同 merge。

## 8. 已知设计取舍

- 广播-only 发现对 AP 隔离/跨网段无效 → 四层兜底:名片(定案新增)> 手动添加 IP + probe_targets + 中继名册。
- ReplayGuard 容量 4096 是内存/安全折中;溢出拒绝新 nonce(保守)。
- Windows tokio UDP 缺陷的规避(专用线程)是有意为之的架构例外,勿"优化"回 tokio。
- 包内容 6 字段永不扩(无 IP/目录/能力清单)——质量探测等新能力一律不进广播,按需单独通道(见 16 篇)。
