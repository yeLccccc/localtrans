# 05 共享目录与远程文件操作

> 源码:`crates/localtrans-core/src/share.rs`(616 行)、`share_watch.rs`(219 行);路由分支在 transfer/engine.rs。

## 1. 设计目标

- 用户显式把若干本地目录登记为"共享区"(id + 别名 + 路径),对端配对后可浏览/下载。
- 浏览响应必须防御路径穿越/符号链接逃逸(五重防御)。
- 共享区内容变化时**主动通知**对端(watchdog + SharesChanged),浏览页自动静默刷新。
- 远程文件操作(改名/删除/建目录)v0.6.0 起,删除必须经本地用户确认门。

## 2. ShareRegistry(share.rs)

```rust
ShareRegistry { shares: Arc<RwLock<Vec<ShareDef>>> }   // Clone = 句柄复制,watchdog 与路由器同视图
ShareDef { id: String, alias: String, path: PathBuf }  // 持久化在 config.json
```

API:`list / add(同 ID 覆盖) / remove / share_id_of_alias / resolve / list_dir / op_rename / op_delete / op_mkdir`。

### 2.1 resolve 五重防御(L64)

1. `Component` 迭代拒 ParentDir/Prefix/RootDir;
2. 字符串含 `:` 拒(盘符);
3. canonicalize 后必须 starts_with canonical root;
4. `symlink_metadata` 拒 reparse point(Windows 0x400)/symlink;
5. 返回 canonicalized 路径。

### 2.2 list_dir(L131)

- limit 上限 500(路由器固定每页 200);跳过 `.` 开头与 Windows HIDDEN/SYSTEM 属性;
- 条目 >50000 → `TooManyEntries`(M-B8 防内存放大);
- 按 name 排序后 cursor 偏移分页 → `(Vec<FileEntry{name,is_dir,size,mtime}>, Option<next_cursor>)`。

### 2.3 远程操作(v0.6.0)

| 操作 | 约束 |
|---|---|
| op_rename | new_name 必须纯文件名;目标已存在拒 |
| op_delete | 目录 = remove_dir_all;**必须过 DeleteAsk 确认门**(见 §4) |
| op_mkdir | 创建后校验仍在 root 内,越界回滚删除 |

权限:三分支都要求 browse;未授权回 `ShareOpResult{ok:false,"无操作权限"}`。

## 3. watchdog(share_watch.rs)

**不用 notify/inotify** —— 明确取舍(文件头注释):2s 周期浅扫根目录一层。

- `dir_fingerprint()` = 排序条目 (name,is_dir,size,mtime) 的 FNV-1a;读不了目录返回 u64::MAX(存在→读不到也算变化)。
- 隐藏项跳过(与 list_dir 对齐);每 share 独立比对;首轮建基线不通知。
- **空闲指数退避** 2s→4s→…→30s 封顶;任一变化立即归位。
- 扫描在 spawn_blocking(不卡 runtime);已删共享区清基线防泄漏。
- 变化回调(壳层负责):① emit 前端事件(PC:`shares-changed`)② 对所有已连接对端发 `ControlMsg::SharesChanged{share_id}` → 对端浏览页防抖静默刷新。

## 4. 删除确认门(S7/S8/S9,跨 core+双壳)

```
对端 ShareDelete ──▶ RPC 路由器:resolve → 目录计数(spawn_blocking,上限10000)
                  → delete_permits Semaphore(8) 并发限
                  → 发 DeleteAsk{ask_id, from, share_id, name, is_dir, entry_count, deadline}
                  → 壳层弹确认框(PC: delete-request 事件 / Android: DeleteRequested)
                  → respond(oneshot) —— 超时/通道关闭/拒绝 全部 fail-closed(不删)
                  → 确认才 op_delete(spawn_blocking)→ 回 ShareOpResult
```

## 5. 浏览页数据流(PC)

```
SharesReq → 共享区列表(左栏)
ListReq{share_id, path, cursor} → FileEntry[](右栏,面包屑+分页"加载更多")
选中文件 → start_download(文件)/ start_download_dir(文件夹整棵直拉)
hover 文件夹行 → 「下载」按钮(v0.2.6)
SharesChanged(本机/远端) → 500ms 防抖静默刷新(空闲时才刷,避免与用户操作打架)
```

Android:`remote_shares / list_remote / share_op` 三 FFI(无 cursor 分页,一次拉全)。

## 6. 已知取舍

- 轮询 watchdog 而非 OS 事件:实现简单、跨平台一致、无依赖;代价是最多 2s(空闲后退避到 30s)延迟与少量常驻扫描 CPU。浅扫一层:深层变化靠用户刷新/重新进入目录。
- 浏览分页 200/页 + cursor:大目录(>50000 条)直接拒绝,防对端内存放大。
