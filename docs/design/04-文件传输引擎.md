# 04 文件传输引擎

> 源码:`crates/localtrans-core/src/transfer/`(engine.rs 7177 行 / manifest.rs / dedup.rs / adapt.rs / sender_state.rs / source_probe.rs / mod.rs)。

## 1. 设计目标

- 单引擎支撑三种角色:**接收方(destination)**、**推送方(source-push)**、**被取方(source-pull)**。
- 分块传输(4 MiB/块、逐块 SHA-256 校验)、接收侧位图断点续传、整文件哈希秒传。
- 滑动窗口 + 自适应并发流(2-32),窄带(中继)与局域网都能跑满。
- 接收侧落盘绝对安全:多层文件名净化、临时 parts 目录、原子 finalize。

## 2. 核心常量与结构

| 常量 | 值 | 说明 |
|---|---|---|
| CHUNK_SIZE | 4 MiB | 块大小(protocol.rs) |
| CHUNK_HEADER_LEN | 12 B | job_id u64LE + chunk u32LE |
| SMALL_FILE_LIMIT | 1 MiB | 小文件阈值(offer 时即算整文件 hash) |
| BufferPool | 32 × 4MiB 许可 | **128 MiB 在途硬上限**;crossbeam SegQueue 复用;BufferGuard RAII Drop 自动还池 |
| LOCALTRANS_IDLE_TIMEOUT_SEC | 90s | 全传输无字节进展判死(取代单块 60s 硬超时,窄带单块 >107s 会误杀) |
| LOCALTRANS_TRANSFER_MAX_SEC | 1800s | 推送等 JobDone 的静态兜底上界 |

任务注册表(进程级 OnceLock+std Mutex,临界极短):`task_controls`(job→控制通道)、`push_jobs`(offer_id→文件清单)、`push_controls`(offer_id→{paused, cancelled})、`sender_jobs`(发送侧任务)、hook 表(ask/delete/auto/recv)。

## 3. 拉取流程(浏览页"下载",start_pull_parts L599)

```
1. send_rpc(MetaReq) ──10s──▶ MetaResp{job_id, file_name, total_size, chunk_hashes}
2. Manifest::from_meta_with_source(记录 peer/share/rel 溯源)
3. 断点检测:pending_jobs(parts_root) 找 (file_name,total_size,chunk_hashes) 全匹配旧目录
   → 命中复用旧 job_id(位图续传);否则新建 .localtrans-parts/{job_id:016x}/
4. 空文件:直接 finalize + RecvAck + Done
5. PartWriter::load_or_open:manifest.json 存在且三元组匹配 → 续用位图,发 Resumed{already_bytes}
6. spawn 速度探测任务(500ms):conn.path stats → loss/rtt/cwnd → adapt.on_probe 调窗
7. 批循环:消化 Pause/Resume/Cancel → 窗口 = adapt.current() → run_receiver_windowed 收一批
8. 收齐 → finalize(dest_root) → RecvAck{job_id} → Done
```

**接收窗口化**(run_receiver_windowed L1423):滑动窗口 `sent - completed ≤ window`;refill 宏补发 FetchReq;每块一条 uni 流,JoinSet 收割:读 12B 头(校验 job/chunk)→ pool.acquire → **64KiB 分段读并逐段刷新 idle 时戳** → 锁外算 SHA-256 → `write_chunk_preverified` → ChunkDone(try_send 可丢)。

## 4. 推送流程(push_files_rel_cancellable L916)

```
1. 逐文件 metadata;≤1MiB 当场算整文件 sha256 放入 OfferFile.hash(大文件 hash=None)
2. 有大文件 → 先 register_push_job_rel(必须先于 OfferReq!否则对端 accept 后
   反向 MetaReq 落空 30s 超时竞态)
3. send_ctrl(OfferReq{job_id, files})
4. 等 OfferResp:订阅 push_signals 广播;总超时 offer_timeout_secs+30;
   5s 轮询 cancel(BUG01:对端离线时占位任务可取消)
5. 解出 (accepted, save_dir, reason, skip_bitmap)
6. 小文件秒传位图:skip_bitmap 与 files 等长,按索引剔除已持有文件
7. !accepted → remove_push_job + OfferRejected/OfferTimeout
8. 小文件:send_small_files_batched —— 单条 uni 流逐文件
   [u16名长][名][u16rel长][rel][u64大小BE][数据];发前逐文件 Started
9. 大文件:只发 Started;实际发送由接收方反向 MetaReq/FetchReq 驱动(见 §6)
10. 等 JobDone/JobFailed(1800s 兜底;5s 轮 cancel)
11. 收尾:remove_push_job(无论成败防泄漏);按数量补发 Done;整 job Done
```

## 5. 接收侧写盘(PartWriter,L103-306)

- 任务目录 `<下载根>/.localtrans-parts/{job:016x}/`:`part.bin`(随机写)+ `manifest.json`(块位图,收齐或 >1s 节流保存)。
- `write_chunk_preverified`:先比对 hash 与 chunk_len(不符=HashMismatch);哈希在**锁外**算(4MB~10ms,锁内会串行化);Windows 用 seek_write。
- **Drop 兜底**:part.bin 还在 → 强存 manifest(任何异常退出路径位图不丢)。
- `finalize(dest)` L235:强存 manifest → **第三道文件名净化** → missing 非空=Incomplete → `file.sync_all()`(强制刷盘防"已完成"截断)→ 冲突 `name (1).ext` 递增(100 次封顶)→ rename(part.bin→最终)→ 删任务目录。

**parts 恒在默认下载根**(不跟另存目录走,防残留);另存目录只接收 finalize 后的成品。

## 6. 推送大文件接收侧(recv_push_large_file L1253)

```
1. 目标 = save_root/rel_dir(逐段 sanitize_component)
2. send_rpc(MetaReq{share_id:"push:{offer_id}", path:"rel/name"}) ──30s──▶ MetaResp
3. sanitize_file_name(file_name);total_size != OfferFile.size → 拒(P0-4 防偏移扩展)
4. 大文件秒传:file_hash 非空且 InboxIndex.lookup(hash,size) 命中
   → place_dedup_copy(硬链优先)→ RecvAck → InstantHit 事件 → return(零块传输)
5. 否则 PartWriter 窗口化接收(固定 window=4),每整窗回发 RecvProgress{cumulative_bytes}
6. finalize → RecvAck → Done → 索引进账
```

## 7. OfferReq 决策与接收编排(handle_offer_decision L2326)

- save_dir 产生:Auto 档 = config.download_dir;Ask 档 = UI OfferAsk.respond 返回的用户目录;无则回落默认。
- **秒传位图**(仅 accepted 时计算):`size ≤ 1MiB && inbox_index.lookup(hash,size).is_some()`;拒绝时回空位图(**不回显 hash,防 A5 oracle 探测接收方已有文件**)。
- accepted → spawn 接收编排任务:阶段1 小文件批流接收(位图命中的本地复用+InstantHit)→ 阶段2 逐个大文件 → Ok=JobDone / Err=JobFailed+Failed 事件。

## 8. 秒传/去重(dedup.rs)

- 粒度:**整文件 SHA-256**;索引 = 下载根 `.localtrans-inbox-index.json`,`HashMap<hash, {path, size}>`。
- lookup 要求 size 一致;prune_missing 惰性清失效项;损坏→空索引(秒传退化普通传输,不阻断)。
- place_dedup_copy:源==目标直接返回;冲突递增;**硬链优先**,失败回退 copy。
- 进账三路径:小文件批流后(内容 hash 自算)/ 大文件 MetaResp hash 完成后 / 秒传复用后。查询两路径:OfferReq 决策(小文件位图)/ 大文件 MetaResp 后。

## 9. 流控与自适应(adapt.rs + source_probe.rs)

- `AdaptiveStreams`:初始 4 流(窄带中继 16 流单块 >107s 实测根因);`on_probe(bps, loss)`:loss>5% → max(2, cur-2);bps 涨 >5% → +1(封顶 32)。
- 拉取侧:500ms 探测任务驱动调窗;推送大文件接收侧固定窗口 4。
- 发送侧限速:`TransferCtl::Throttle{max_streams}` → throttle_cap(PC 端"限速菜单" 1/2/4/不限)。
- `SourceProbe`(发送侧,source_probe.rs):500ms 周期发 SourceSpeed{bps,loss,rtt,cwnd,streams,remote_done};**空闲自杀 60s**(120 tick 无进展且无在途流)——小文件推送无人收尾,常驻空转曾是 CPU 元凶;空闲退出不删 sender_jobs(长暂停后 RecvAck 仍需找到任务)。

## 10. 发送侧状态(sender_state.rs)

`SenderJobState{job_id, src_path, manifest, bytes_counter, active_streams, throttle_cap, progress_tx, probe_stop, paused/cancelled, offer_id, remote_done}`。

终态清理五路径:RecvAck→SourceDone(删)/ TransferCtl Cancel / 自身 cancelled → SourceFailed(删)/ 连接关闭 30s 兜底删(持写锁绝不 await,M-C5)/ 推送失败按 offer_id 反查删。

## 11. 文件名/路径净化(接收侧安全链)

| 函数 | 层 | 规则 |
|---|---|---|
| `sanitize_file_name` | 文件名 | 剔控制符+bidi 控制符(U+202A-202E/2066-2069);拒空/分隔符/`..`/Windows 22 保留名/尾点尾空格/>255B;错误不回显原名 |
| `sanitize_component` | 目录单段 | 拦 `..`/盘符/分隔符 |
| `sanitize_rel_parent` | 拉取 rel | parent 逐段净化,绝对路径/`..`/`:` 拒 |
| finalize 内再净化 | 第三道防线 | "防未来调用点漏过入口校验" |

净化链:批流文件名 → rel_dir 逐段 → MetaResp file_name(+size 交叉校验)→ finalize 第三道。冲突一律 `name (n).ext`。

## 12. 文件夹传输

- **拉取** start_pull_dir(L2819):`list_remote_dir_recursive` BFS ListReq 分页(深度 ≤32、文件 ≤10000、15s/页)→ dest=下载根/净化(文件夹名) → 逐文件串行 start_pull_parts(parts 恒在下载根)→ DirPullEvent(Enumerated/FileDone/FileFailed/AllDone)。
- **推送**:rel_dir 全链路 —— OfferFile.rel_dir → 批流帧 rel 字段 → 大文件 MetaReq path="rel/name" → resolve_push_file 组合匹配 → 落盘自动建子目录。
- PC 壳展开本地侧:`expand_local_paths` BFS(深度 ≤32、≤10000 文件、系统敏感目录黑名单、跳隐藏)。

## 13. 断点续传与 GC

- 接收侧位图(manifest.json)即全部状态;发送侧无状态(按 FetchReq 现读源文件)。
- `pending_jobs`:扫 parts 目录找有缺失块的任务(重启恢复/续传入口)。
- `gc_stale_parts`:位图全真孤儿直接删(完整性存疑);mtime >7 天删。
- 启动迁移:active/pending/paused → interrupted;push 方向或有 parts 的保留;孤儿接收任务丢弃。

## 14. 事件(ProgressEvent,L420)

接收:Started / Resumed{already} / ChunkDone / Speed / Done / Failed / InstantHit
发送:SourceStarted / SourceChunkDone / SourceSpeed{...remote_done} / SourceDone / SourceFailed
文件夹:Enumerated / FileDone / FileFailed / AllDone

纪律:**高频事件 try_send 可丢,终态事件 await 保证送达**(M-C4)。

## 15. 线程/任务清单(传输域)

| 任务 | 生命周期 |
|---|---|
| spawn_rpc_router | 常驻(消费 inbound_ctrl) |
| 拉取编排 + 500ms 探测 | 任务存活 |
| 每块接收(JoinSet)/ 每块发送 | 单块 |
| OfferAsk / DeleteAsk 等待子任务 | ≤ 超时(**路由器循环绝不 await 用户**) |
| OfferReq 接收编排 + 事件泵 | 整 offer |
| SourceProbe | stop/conn.closed/60s 空闲 |
| 连接关闭 30s 兜底清理 | conn.closed+30s |

锁粒度:PartWriter `Arc<tokio::Mutex>`(SHA-256 锁外);sender_jobs RwLock(读=FetchReq 热路径,写只包 remove);全局表 std::Mutex 临界极短。
