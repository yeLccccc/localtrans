# 13 线程与任务模型

> 全系统线程/tokio task/锁清单与并发纪律汇总。

## 1. 总览

- **唯一 OS 线程例外**:discovery(阻塞 std UDP socket,规避 Windows tokio UDP recv 冻结缺陷);**其余全部 tokio 异步任务**。
- Android FFI:自建 `tokio::Runtime`(2 worker, enable_all),全部 FFI 调用 `ffi_guard` 包 `block_on`。
- PC 壳:Tauri 自带 async runtime;`setup` 内 `block_on` 完成同步初始化。

## 2. 任务清单(按域)

### 发现(discovery 线程内单循环)
非阻塞 try_recv 命令 → 250ms 超时 recv_from → 三时间节拍(presence 5s±1s / 重探 8s每目标 / 过期 15s 扫描,1s 节拍检查)。Drop 停线程+join。

### 会话(session.rs)
| 任务 | 生命周期 |
|---|---|
| accept 循环 | 随 endpoint |
| handle_incoming(每传入连接) | 至会话建立 |
| ctrl_loop(每会话) | 连接存活;select{出站 ctrl_rx, 入站 read 增量解帧} |
| 同意门超时任务 | 一次性 sleep_until(锁内代次校验,锁外关连接) |

### 传输引擎(transfer/)
| 任务 | 生命周期 |
|---|---|
| spawn_rpc_router | 常驻;**主循环绝不 await 用户决策**(Ask 独立子任务) |
| OfferAsk / DeleteAsk 等待子任务 | ≤ 超时 |
| 拉取编排 + 500ms 探测 | 任务存活 |
| 每块接收(JoinSet)/ 每块发送(每 FetchReq) | 单块 |
| OfferReq 接收编排 + 事件泵 | 整 offer |
| SourceProbe | stop/conn.closed/**60s 空闲自杀** |
| 连接关闭 30s 兜底清理 | conn.closed()+30s |
| share watcher | 常驻;spawn_blocking 扫描;空闲退避 2s→30s |

### 中继客户端
| 任务 | 生命周期 |
|---|---|
| run_background | 常驻;select{15s Ping, recv_uni};断线内联重连循环 |
| connect_peer(发起时) | punch → KNOCK → 握手(调用方任务内) |
| accept_peer(PunchNotif 触发) | 10s 超时 accept |
| quinn 内部驱动 VirtualUdp | 随 Endpoint |

### 中继服务器
| 任务 | 生命周期 |
|---|---|
| server.run 主循环 | select{accept→spawn handle_conn, 5s reap, 30s ratelimit} |
| handle_conn(每控制连接) | 连接存活 |
| data_plane recv_loop | **端口池每端口一个**,常驻 |

### PC 壳事件桥(main.rs,常驻任务)
会话事件泵 / 发现 watch / 接收泵 recv_rx / ask 泵 / auto 泵 / delete_ask 泵 / source 泵 / 传输聚合泵(4Hz/1Hz 动态)/ 持久化泵(1s 脏标记)/ 共享 watchdog 回调 / 中继事件桥 / 防火墙自检。

### FFI 壳
五事件泵(直接 callback.on_event)+ 会话事件桥(回路1/2)+ 发现 watch + 持久化循环 + spawn_relay。

## 3. 锁清单与粒度

| 锁 | 类型 | 临界区纪律 |
|---|---|---|
| sessions | tokio Mutex | 短临界;删除前代次校验 |
| trust | tokio Mutex | 短临界(get/upsert/save 分离) |
| config | tokio RwLock | 读写分离 |
| cooldown | tokio Mutex | 插入前顺手清过期 |
| pending_rpcs | std Mutex | 同步上下文极短(oneshot 表) |
| sender_jobs | tokio RwLock | **读锁=FetchReq 热路径;写锁只包 remove,持写锁绝不 await**(M-C5) |
| PartWriter | Arc<tokio::Mutex> | 串行化写盘;**SHA-256 在锁外算** |
| 租约表(服务器) | std RwLock | 微级临界 |
| 学习表(服务器) | tokio RwLock | 每包查改 |
| 进程级注册表(task_controls/push_jobs/push_controls/hook 表) | OnceLock+std Mutex | 极短 |
| FFI state | OnceLock | 初始化后读零锁 |

## 5. 并发纪律(改动前必读)

1. **select! 取消安全**:入站读用 `read`(单次完成)+ 手动 inbuf;禁 select 内 read_exact(v0.1.5 字节丢失实机 bug)。
2. **锁内不 await**(取数据出锁再 await);持写锁绝不发事件(M-C5)。
3. **终态事件 await,高频事件 try_send**(M-C4)。
4. **会话删除先验代次**(M-B1)。
5. **哈希计算在 PartWriter 锁外**。
6. **路由器主循环不 await 用户**(Ask 子任务化)。
7. **占位任务必须有取消路径**(BUG01:对端离线不挂死)。
8. **BufferGuard RAII** —— 任何 `?`/abort 路径缓冲自动还池。
9. **RAII 句柄 Drop 停线程/任务**(DiscoveryHandle;服务器 ConnGuard)。
10. **MSYS/Windows 差异**:discovery 阻塞线程是有意例外,勿改回 tokio。
