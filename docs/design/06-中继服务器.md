# 06 中继服务器(localtrans-relay)

> 源码:`crates/localtrans-relay/src/`(main.rs / lib.rs / config.rs / control.rs / data_plane.rs / lease.rs)。部署文档:`docs/relay-deploy.md`。

## 1. 设计目标

- 自建、轻量、单二进制:帮助 NAT/跨网两端建立"中继转发的端到端加密会话"。
- **两平面**:控制面(QUIC)做认证/注册/名册/Punch;数据面(裸 UDP)逐包转发密文。
- **零知识**:中继看不到任何文件明文(内层 QUIC 端到端加密),只做端口级路由。
- 公网安全:PSK 准入、注册签名(占有证明)、速率限制、并发上限、载荷上限。

## 2. 总体架构

```
客户端 A ──QUIC 9443(控制)──▶ relay ◀──QUIC── 客户端 B
    │                            │
    │   Register(PSK→nonce→签名) │  名册 Roster 广播 / Punch 协商
    │                            │
    └──UDP 9000-9100(数据)──▶会话端口◀──UDP──┘
         [18B头][密文内层QUIC包] 剥头转发
```

- 数据面端口池 `data_port_start..data_port_end`(默认 9000..9100):**设备租约端口与会话端口共用同一池**。
- 名册里的 `lease_addr = public_ip:租约端口` 只是"逻辑地址";实际转发发生在 Punch 分配的**会话端口**。

## 3. 控制面协议(control.rs + core/relay/proto.rs)

### 3.1 帧格式

`[4B 大端长度][JSON]`,上限 64KB(分配前检查,防 pre-auth 内存放大)。请求走 bi 流;**服务端推送走 uni 流**(每条消息一条)。

### 3.2 消息表(RelayMsg)

| 消息 | 方向 | 字段 |
|---|---|---|
| Register | C→S | name, fingerprint[32], hidden, cert_der, nonce_sig[64] |
| Ping | C→S | — |
| Punch | C→S | target_fp |
| Leave | C→S | — |
| ServerNonce | S→C | nonce[32] |
| RegisterAck | S→C | lease:Option<{data_port, token[16]}> |
| Roster | S→C | rev(u64 递增), devices:[{fingerprint,name,lease_addr,relayed_ephemeral}] |
| PunchNotif | S→C | target_fp(=请求方), target_lease(会话地址) |
| PunchResp | S→C | ok, reason?, session_addr? |
| Error | S→C | code(1=PSK 错/2=首条非 Register/3=占有证明失败), msg |

### 3.3 注册握手(control.rs handle_conn L325-420)

```
1. QUIC 握手(ALPN localtrans-relay;客户端自签临时证书,不验服务端证书)
2. 客户端首条 bi 流:export_keying_material(b"localtrans-relay-psk", psk) 32B 证明
   → 服务端恒时比较;失败 = Error(1) + 断连 + 记认证失败
3. 服务端推 ServerNonce(32B 随机,占有证明挑战)
4. 客户端第二条 bi 流:Register{..., nonce_sig = sign(fp ‖ nonce)}
5. 服务端 verify_possession(fp, cert_der, signed, nonce_sig) 三验
   (声明指纹==SHA256(证书) + 证书公钥验签)→ 失败 = Error(3) + 断连
6. leases.alloc(fp,name,hidden) → RegisterAck{token, data_port} → 广播名册
   重复注册同 fp:换新 token、端口保留
```

**PSK 通道绑定**:证明 = TLS exporter 输出,绑定到具体 QUIC 连接(防重放搬运);PSK ≥16 字节(config 校验,历史教训:曾静默回退 dev-psk 公网裸奔,P0-3 已改严格启动)。

### 3.4 心跳与名册

- 客户端每 15s Ping → `heartbeat(fp)` 刷 last_ping + 顺带推 Roster(排除自己)。
- 名册 rev 原子递增;注册/离开/租约回收都触发广播。

### 3.5 Punch 流程(L566-643)

```
请求者 Punch{target_fp}
  → 目标隐身? 视同不在线(不泄露在线状态)
  → punch 速率限制:每 fp 60s 滑窗 ≤10 次
  → leases.alloc_session_port(请求者,目标) 从端口池分配会话端口 + 登记双方成员(S3)
  → 向目标推 PunchNotif{请求方fp, 会话地址}
  → 向请求者推 PunchResp{ok:true, session_addr}
目标不在线 → PunchResp{ok:false,"对方当前不可达"}
```

### 3.6 连接生命周期

- `Leave`:移除租约+连接+广播;客户端 shutdown:发 Leave → sleep 100ms → close。
- 控制连接断开 → 立即回收租约并广播(token 随重注册换新,不给 45s 宽限)。

## 4. 数据面(data_plane.rs)

### 4.1 包头(18B)

```
[1B 版本=0x01][1B 标志][16B token]
标志: 0x00=DATA(转发) / 0x01=KNOCK(只学习) / 0x02=GOODBYE_KNOCK(回收)
载荷上限 1500B(含头 1518,防反射放大;超限丢)
```

### 4.2 每端口一个 recv_loop(L132-280)

```
解头(坏头静默丢) → 载荷超限丢 → token 验证得 src_fp(顺带刷 last_active)
→ S3 会话成员校验:只有 Punch 登记的双方可在此端口发包(非成员丢+计数)
→ touch_session(刷活跃)
KNOCK:      学习表 learned[port][src_fp] = 发送方真实公网出口;不转发
GOODBYE_KNOCK: 清该 fp 学习记录;端口学习表空 → 回收会话端口
DATA:       NAT 漂移检测(源地址变了重学习)→ 按成员差集找对方 fp
            → 取学习表地址 → 剥 18B 头 → 同 socket send_to 转发;对方未 KNOCK 则丢
```

**"KNOCK 打洞"语义**:双方都把包发往中继会话端口,中继学习各自 NAT 出口后互相转发——并非真 NAT 打洞,本质是"学习式转发"。KNOCK 必须从 VirtualUdp 自己的 socket 发(临时 socket 会让中继学到已丢弃的端口)。

## 5. 租约(lease.rs)

```rust
LeaseEntry { fingerprint, name, port, token[16], last_active(数据面), punch_from, last_ping(控制面), hidden }
```

- TTL 默认 45s;**回收条件 = last_active > TTL 且 last_ping > TTL**(双平面任一活跃即保活)。
- 服务端主循环 5s reap_tick;空闲会话端口 2×TTL(90s)连带回收(断电断网兜底)。
- 30s ratelimit_tick:清过期拉黑/认证失败窗口/punch 速率条目。
- 纯 std RwLock(临界区微级,不用 tokio 锁)。

## 6. 服务器配置(config.rs,TOML)

| 字段 | 默认 | 说明 |
|---|---|---|
| control_port | 必填 | 控制面 QUIC 端口(生产 9443) |
| data_port_start / data_port_end | 必填 | UDP 端口池(9000/9100) |
| public_ip | 必填 | 名册 lease_addr 拼接用 |
| psk | 必填 | ≥16 字符;启动打 sha256 前 8 字节摘要(不暴露 PSK) |
| lease_ttl_secs | 45 | 租约 TTL |
| auth_max_per_min | 5 | 认证失败窗口 |
| max_bps_per_pair | None | 预留 v1 不实现 |

严格加载:文件缺失/解析失败/psk 过短一律**拒绝启动**。命令行唯一参数 = 配置路径(默认 /etc/localtrans-relay.toml);RUST_LOG 控制级别。

## 7. 防滥用(S4-S7 + 既有)

| 机制 | 值 |
|---|---|
| 认证失败拉黑 | 每 IP 60s 内 ≥5 次 → 拉黑 10 分钟 |
| Punch 限速 | 每 fp 60s ≤10 次 |
| 全局并发控制连接 | ≤512(fetch_add 预占防竞态) |
| 单 IP 并发连接 | ≤8(ConnGuard Drop 兜底防漏减) |
| 读超时 | 证明 10s / Register 等待 10s(防半开占位) |
| 推送超时 | 3s 踢慢读者 |
| 帧上限 | 64KB;数据载荷 1500B |

## 8. 线程模型

- `main`:配置 → spawn server.run → 等 ctrl_c → shutdown。
- `RelayServer::run`:单 select{accept(每连接 spawn handle_conn)、5s reap、30s ratelimit}。
- `DataPlane::spawn`:端口池每端口一个 recv_loop 任务。
- 学习表 tokio RwLock;租约表 std RwLock。

## 9. 已知局限(注释自认,设计文档如实记录)

- PunchResp 与等待者匹配"取第一个等待者"不按 target_fp 索引(client.rs L287 注释)——并发 punch 多目标时可能错配。
- 学习表无 TTL,依赖 GOODBYE / 会话端口 2×TTL 回收。
- 单端口单 recv_loop(非 batch recv)性能有上限。
