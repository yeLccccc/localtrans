# 07 中继客户端与自动愈合

> 源码:`crates/localtrans-core/src/relay/`(mod.rs / client.rs / proto.rs / virtual_ep.rs / autoheal.rs)。服务器侧见 06 篇。

## 1. 设计目标

- 客户端把中继抽象成"另一条 QUIC 路径":与直连共用同一套 session 配置/证书/消息,**差异只在底层 socket**(真 UdpSocket vs VirtualUdp)。
- 断线自愈:控制连接断开自动退避重连+重注册;对端会话死亡自动重建(Punch 重走);失败的传输任务自动续传一次。
- UI 无感:设备列表自动并入名册设备(via_relay 徽章),连接命令双路由(本地优先/名册兜底)。

## 2. RelayClient(client.rs)

### 2.1 连接与注册(do_connect L112-192)

```
QUIC 握手(NoVerify 服务端证书 + 自签临时客户端证书, ALPN localtrans-relay)
→ bi 流1:PSK 证明(exporter)
→ 收 ServerNonce
→ bi 流2:Register{name, fingerprint, cert_der, nonce_sig=sign(fp‖nonce)}
→ RegisterAck{token[16], data_port}
→ 状态 Registered
```

初次 `connect()` 即无限重连循环(1s 起指数退避封顶 30s);名字空兜底 "LocalTrans"。

### 2.2 后台任务(run_background L196-255)

单任务 select:
- **15s Ping tick**:维持控制面心跳;失败触发重连;
- **recv_uni**:逐条 accept uni 流分发服务端推送:
  - `Roster` → 更新名册 → `RosterUpdated` 事件(壳层 merge 进设备列表);
  - `PunchNotif` → **自动应答**:VirtualUdp::bind → KNOCK → server_endpoint_pinned(钉扎请求方指纹)→ 10s accept → 内层 QUIC 握手 → `sm.adopt_connection`(对端会话表接管);
  - `PunchResp` → oneshot 唤醒等待中的 connect_peer。
- 断线 → `on_disconnect`(置 Reconnecting、清连接/punch 等待表)→ 内联重连循环 → 成功重走完整注册(新 token)。

### 2.3 connect_peer(发起方,L353-395)

```
bi 流发 Punch{target_fp} → 等 PunchResp(会话地址)
→ VirtualUdp::bind(token, 会话地址)
→ vudp.send_knock()
→ client_endpoint(vudp, id, expected_fp=目标) + mTLS 客户端证书
→ ep.connect(会话地址, "localhost") → 内层 QUIC 握手 → sm.adopt_as_initiator
```

### 2.4 事件与状态

- `RelayEvent{RosterUpdated / StatusChanged / PunchIncoming}`(mpsc 32);watch 状态 Connecting/Registered/Reconnecting。
- `validate_relay_config`(mod.rs):非空、SocketAddr 可解析(细分错误)、psk ≥16 —— 双壳共用单一实现。

## 3. VirtualUdp 虚拟端点(virtual_ep.rs)

实现 quinn `AsyncUdpSocket` trait —— "虚拟网卡":

| 方法 | 行为 |
|---|---|
| bind(token, 会话地址) | 绑 0.0.0.0:0 并 connect() 到会话地址(默认目标+入包过滤) |
| try_send | 只允许发往会话地址;出站 = 18B 头(DATA)+ QUIC 包;错误静默返回 Ok(丢包靠 QUIC 重传兜底,防紧密重试风暴) |
| poll_recv | 单包收;头 18B 合法且 token 匹配 → 剥头;否则按裸载荷交付;**RecvMeta.addr 恒宣称会话地址**(quinn 看到的"对端"恒为中继会话端口,两端逻辑地址一致) |

三个端点工厂(与直连统一配置):
- `server_endpoint_pinned`(accept_peer 用):`server_config_pinned` **握手期**钉扎客户端指纹;idle 覆写;max_udp_payload_size(1200)。
- `client_endpoint`(connect_peer 用):附自签客户端证书(mTLS,否则对端 NoPeerCert);可选钉扎。
- `server_endpoint`:无钉扎旧版保留。

**MTU 纪律**(三层):控制面 endpoint `mtu_discovery_config(None) + initial_mtu=min_mtu=1200`;数据面 VirtualUdp `max_udp_payload_size(1200)` + relay_transport_config(探测关死)。原因:quinn 0.11 探测会涨回 1452+,跨网路径(WSL 过滤器/PPPoE)持续 WSAEMSGSIZE(10040) → 控制连接反复断连 → 名册重推 = 设备列表"闪现"。`max_udp_payload_size` 只管接收侧,发送侧必须关探测 + 压 initial_mtu。

## 4. 自动愈合(autoheal.rs,双壳共用)

### 4.1 控制连接重连(client.rs 内)

Ping 失败/uni 流错误 → on_disconnect → 1s 起指数退避封顶 30s 重连 → 重注册(新 token)→ 名册由服务器重推。

### 4.2 对端会话重连(回路 1)

```
SessionDown{fp} → 壳层检查:本地发现无此设备 && 中继名册有
  → healing_fps 去重 → emit peer-reconnecting{active:true}(卡片"重连中…")
  → auto_reconnect: reconnect_peer_conn(connect_peer 带 BackoffState 重试)
      BackoffState: 1s→2s→… 封顶 30s;MAX_FAILS=3,第3败放弃
  → 成功 → sm.adopt_as_initiator(会话恢复) → active:false
  → 失败 → active:false(等下次 SessionDown 再触发)
```

### 4.3 传输自动续传(回路 2)

```
SessionUp{fp} → auto_resumable_jobs:传输表中 state=failed && 对端匹配
  && parts 残留 && 未自动重试过 → 直接 resume_pending(每个任务只自动重试 1 次)
```

## 5. 壳层接线

| 职责 | PC(main.rs) | Android(relay_state.rs) |
|---|---|---|
| 启动/重启 | config.relay_enabled → spawn RelayClient::connect + 事件桥 | spawn_relay 同构 |
| RosterUpdated | debug 日志 + merge → device-list | 更新名册 + DevicesChanged |
| StatusChanged | emit relay-state(推) | RelayUiStatus(拉,relay_status()) |
| PunchIncoming | accept_peer + adopt_connection + 刷徽章 | 同左 |
| 配置校验 | validate_relay_config(接命令层) | validate_relay(FFI 暴露) |
| hidden 翻转 | reconnect_relay(重注册) | spawn_relay 重走 |

M-B3 防双连:connect 任务句柄存 relay_connect_task,重启前 abort 旧任务。

## 6. 设备合并(device_merge.rs)

`merge_devices(本地发现, 名册, connected, 别名, 信任表) -> Vec<MergedDevice>`:

1. 本地发现优先(via_relay=false;online = last_seen<30s);
2. 名册设备 via_relay=true、恒 online;按指纹去重、本地胜;
3. 信任表兜底常驻:已配对但两处都不在 → offline 卡片(addr 不覆盖已有);
4. 显示名:alias > 广播/名册名 > 配对名;
5. 排序全序:connected↓ → online↓ → name↑ → fingerprint↑(tiebreaker 保序,卡片不跳动)。

## 7. 已知坑与纪律

- 发 KNOCK 必须用 VirtualUdp 自己的 socket(client.rs send_knock 临时 socket 版本是死代码)。
- PunchResp 等待者匹配是"取第一个"简化,并发 punch 多目标可能错配(待改 per-target 索引)。
- 中继会话死亡(60-100s 级)在 MTU 修复前是常态;修复后仍需假设会话可能随时死 —— 所以才有 BUG03 的"信任写入不依赖会话"兜底与回路 1/2 自愈。
